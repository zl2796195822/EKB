数据库连接池耗尽的时候，应该按照什么顺序排查？请给我一个标准的操作步骤，并标注每个步骤参考的文档来源。

EKB 智能助手 已核验引用 置信度 94%

根据授权知识库中的标准作业流程，数据库连接池耗尽建议按 「现象确认 → 热点定位 → 根源排查 → 止血处置」 四阶段执行，具体步骤如下：

① 现象确认（1–3 分钟）
先通过监控面板确认连接数是否真的触及 max_connections 上限，并区分「空闲连接堆积」还是「活跃连接打满」两种模式，避免误杀业务。

② 热点定位（3–5 分钟）
使用 SHOW PROCESSLIST + 慢查询日志聚合，优先按 USER + DB + STATE 维度排序，锁定占用连接时间最长的 Top 5 SQL 与业务模块。

③ 根源排查：分别从应用侧连接池配置（泄露、未归还）、SQL 执行计划（全表扫、未走索引）、事务未提交、中间件层配置四个维度递进。

④ 止血处置：优先 KILL 长事务/长查询，再按优先级考虑连接池扩容、只读切换、流量降级等措施。
