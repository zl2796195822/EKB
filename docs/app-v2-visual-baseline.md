# EKB app-v2 视觉基线（M0）

## 1. 基线结论

本文件冻结从零重建 app-v2 的视觉对照边界，不代表生产页面已经完成，也不切换现有应用入口。

- 设计源：/Users/alin/EKB/设计稿/index.html 的实际渲染结果。
- 观察方式：通过本地 HTTP 服务打开设计源，在真实浏览器中查看页面结构和交互状态；不以旧 React DOM、旧 CSS 或旧页面为视觉真值。
- 桌面基线：1181 × 1027 CSS 像素。
- 页面数量：十页，使用十条规范 hash 路由。
- 视觉状态：设计稿中可见的数字、姓名、文档名、时间和应用名是设计样本，不是 app-v2 生产数据。
- M0 交付：冻结页面地图、布局关系、可见模块、交互对照项和适配器边界；只提供 app-v2 最小骨架。

十条规范路由如下，路由清单的单一事实源为 apps/web/src/app-v2/routes.ts：

| 路由 | 页面 | 布局类别 | 里程碑 |
|---|---|---|---|
| #/dashboard | 工作台 / Dashboard | global | M2 |
| #/knowledge | 知识库 / Knowledge Base | knowledge | M3 |
| #/assistant | AI 助手 / AI Assistant | assistant | M4 |
| #/documents | 文档中心 / Document Center | global | M3 |
| #/team | 团队与权限 / Team & Permissions | global | M5 |
| #/analytics | 数据看板 / Analytics | global | M6 |
| #/apps | 应用中心 / App Center | global | M6 |
| #/recycle | 回收站 / Recycle Bin | global | M6 |
| #/profile | 个人中心 / Settings | global | M5 |
| #/modules | 模块地图 / Module Map | module-map | M2 |

搜索能力嵌入知识库、文档中心、AI 助手和全局入口，不增加独立页面。模块地图是可访问页面，不是弹窗；个人中心是可访问页面，不降级为用户下拉菜单。

## 2. 全局视觉与状态规则

### 2.1 全局壳

工作台、文档中心、团队与权限、数据看板、应用中心、回收站、个人中心和模块地图使用 global 或 module-map 壳：

- 左侧全局导航包含品牌、主导航、快捷入口、知识空间、套餐/帮助和用户区域。
- 顶部区域包含当前页面标题、全局搜索、通知、帮助、设置和用户入口。
- 页面内容以浅色画布、白色卡片、细边框、轻阴影、蓝色主色和青绿色辅助色组织。
- 模块地图保留全局顶栏关系，并在内容区提供返回工作台和九个业务模块 tiles。

知识库和 AI 助手使用专用顶栏，不把全局侧栏硬塞入三栏工作区：

- 知识库：专用顶栏 + 左知识空间导航 + 中文件区 + 右知识库概览。
- AI 助手：专用顶栏 + 左会话区 + 中聊天区 + 右知识库上下文/文档预览。

### 2.2 统一状态

所有页面、数据区和可交互能力都必须能表达以下状态：

| 状态 | 视觉与行为基线 |
|---|---|
| loading | 保持设计稿的信息密度和主要尺寸，显示 skeleton、阶段或等待说明，不突然跳变。 |
| empty | 说明空的范围和原因；只有真实可用的下一步才显示操作。 |
| error | 显示可理解的错误、可见的 trace/request 标识（若后端提供）和真实重试入口。 |
| permission-denied | 明确当前主体无权访问，不泄露资源存在性；写操作隐藏或禁用。 |
| unavailable | 明确后端能力缺失，不发假请求、不显示成功 toast。 |
| ready | 只在真实 API 响应或真实 SSE 终态后显示真实结果。 |

M0 页面占位默认使用 unavailable，表示适配器尚未接入，不代表后端请求失败。

### 2.3 禁止事项

- 不复用旧 QAPage、KbPage、SearchPage、OpsPage、DashboardPage、旧布局、旧组件或旧 styles。
- app-v2 的页面、组件、布局、styles 和 visual fixtures 不直接导入旧 UI；未来复用非 UI API client 只能发生在 adapters 内。
- 不从设计稿复制 mock session、静态用户、静态租户、静态 token、假成功数据或假业务 toast。
- 后端没有应用安装、回收站恢复/永久删除/清空、批量删除、资料保存等能力时，保留视觉位置并标记 unavailable 或 disabled。
- M0 不改 App.tsx、main.tsx、旧 pages/components/styles/lib/api.ts、构建配置、依赖或后端。

## 3. 十页逐页视觉基线

以下内容以设计源在 1181 × 1027 桌面视口下的实际渲染为对照。列表中的样本数字和身份仅用于定位设计结构，不能进入生产 view model。

### 3.1 工作台 / Dashboard — #/dashboard

布局类别：global。

可见结构：

- 全局侧栏、全局顶栏、全局搜索、通知/帮助/设置/用户入口和模块地图入口。
- 问候区，包含页面问候文案和新建文档、上传文档、创建知识空间、智能导入四个快捷操作。
- 五张指标卡：知识库文档、知识标签、团队成员、今日访问量、今日 AI 问答。
- 知识库访问趋势图，含时间范围控件和访问量/独立访客图例。
- 知识库使用分布图，含空间分布和总文档数。
- 最近动态列表。
- 最近访问区域，含最近访问/文档/知识库/AI 问答 tabs、表格和查看全部文档。
- 热门标签和知识库健康度卡片，底部为产品 footer。

主要交互：侧栏路由、顶部全局搜索、快捷操作、模块地图、趋势时间范围、分布空间筛选、动态筛选、最近访问 tabs、表格查看/更多、标签查看全部、健康度查看详情。

QA 对照项：

- 首屏必须保留问候、五卡和两组主要图表的层级。
- 没有 dashboard 聚合端点时，指标、图表、动态、标签和健康度使用 loading/empty/unavailable，不显示设计样本数值。
- 智能导入没有对应端点时 disabled；快捷操作只能跳转到真实能力范围。
- 窄屏不得让快捷操作、主要标题或状态说明溢出视口。

### 3.2 知识库 / Knowledge Base — #/knowledge

布局类别：knowledge，专用顶栏三段式。

可见结构：

- 专用顶栏：知识库 / Knowledge Base、搜索知识库/文档/问题、通知、帮助、设置和用户入口。
- 左侧知识空间导航：全部空间、产品设计、研发管理、市场运营、团队协作、知识安全；以及我创建的、与我共享、收藏夹、回收站。
- 中间内容区：全部空间标题和说明、上传知识、筛选、更新时间排序、列表/网格切换、文件表和分页。
- 右侧知识库概览：文档总数、文件夹、共享文档、成员数量、最近更新/热门文档、分类占比和刷新/查看更多。

主要交互：切换知识空间、上传知识、筛选排序、列表/网格切换、表格操作、分页、概览刷新、最近更新/热门文档 tabs、查看全部。

QA 对照项：

- 左导航、中文件区、右概览在桌面视口保持三段式关系；不能把右概览移入独立弹窗。
- 文件夹、收藏、共享、回收站列表若没有真实端点，入口显示 unavailable/disabled，不使用设计样本计数。
- 上传、删除、失败重试、版本和 diff 只能显示真实 API 状态。
- 窄屏先保证当前空间、上传和文件列表可达，侧栏与概览折叠后不能遮挡主要操作。

### 3.3 AI 助手 / AI Assistant — #/assistant

布局类别：assistant，专用顶栏三栏工作区。

可见结构：

- 专用顶栏：知识空间/页面标题、全局搜索、通知、帮助、设置和用户入口。
- 左会话栏：AI 助手标题、新建会话、会话搜索、最近/收藏/项目 tabs、按今天/昨天/过去 7 天分组的会话列表和当前知识空间。
- 中聊天区：会话标题和操作、用户消息、AI 回答、回答阶段、引用列表、耗时/反馈、问题 composer、添加文件/知识库/联网搜索/深度思考/模型选择/发送控件。
- 右上下文栏：知识库连接状态、已使用文档、相关知识、引用文档列表、知识库搜索、上下文条件、文档预览、打开原文和加入引用。

主要交互：新建/搜索/切换会话，分享和会话操作，发送问题，流式阶段和取消，引用查看，反馈，上下文筛选，文档预览、打开原文和加入引用。

QA 对照项：

- 左会话、中聊天、右上下文三栏是核心层级，发送中和错误状态不能移除上下文边界。
- SSE v2 必须可观察 request、retrieval、generation、content、citations、done、错误、heartbeat、turn_id/seq 和 cancel 状态。
- 联网搜索、深度思考、模型选择和 composer 文件上传没有后端能力时保持 disabled/unavailable，并给出原因。
- 引用只能来自当前主体授权的真实 search/SSE 结果；不得用设计样本文档填充生产回答。
- 窄屏需优先保证问题输入、发送/取消、回答和引用入口，左右栏可折叠但不能遮住 composer。

### 3.4 文档中心 / Document Center — #/documents

布局类别：global。

可见结构：

- 全局壳下的 section header：KNOWLEDGE BASE / WORKSPACE、文档中心标题、集中管理说明。
- header 操作：筛选、上传文档。
- 工具栏：文档名称/内容/标签搜索、全部类型、全部空间和批量删除。
- 文档表格：选择、文档名称、所属空间、类型、更新时间、更新者、状态、操作。
- 底部分页和每页数量。

主要交互：筛选、上传、搜索、类型/空间筛选、行操作、分页和每页数量。

QA 对照项：

- section header、工具栏、表格和分页顺序不能改变。
- 批量删除没有批量端点时 disabled，不得让点击产生假请求或成功反馈。
- 服务端不支持的过滤字段不能伪造过滤结果；上传、删除、失败重试、版本/diff 以真实响应为准。
- 窄屏先保证搜索、上传和单行操作，表格允许横向滚动但不能遮挡状态提示。

### 3.5 团队与权限 / Team & Permissions — #/team

布局类别：global。

可见结构：

- section header：KNOWLEDGE BASE / WORKSPACE、团队与权限标题、成员/角色/空间权限说明。
- 导出和邀请成员操作。
- 成员管理、角色管理、权限矩阵三个 tabs。
- 成员姓名/邮箱搜索、全部角色和全部状态筛选。
- 成员表格：成员、所属部门、角色、状态、加入时间和操作。

主要交互：导出、邀请成员、切换 tabs、成员搜索和筛选、表格行操作。

QA 对照项：

- 邀请只能对应真实 invite adapter；用户列表、角色 CRUD、停用、重置密码和权限矩阵写入缺少端点时显示 unavailable/disabled。
- 无权限时不泄露成员是否存在，表格和对应 tab 必须有 permission-denied 或 unavailable 状态。
- 角色和状态视觉标签保持清晰对比，不依靠颜色单独传达信息。
- 窄屏优先保证邀请和 tabs，成员表允许横向滚动，状态和操作列不可被裁掉。

### 3.6 数据看板 / Analytics — #/analytics

布局类别：global。

可见结构：

- section header：KNOWLEDGE BASE / WORKSPACE、数据看板标题和知识流动说明。
- 日期范围按钮，显示近 7 天和日期区间。
- 四张指标卡：文档总数、访问总量、独立访客、AI 问答次数。
- 访问趋势图，含日期轴、访问量和独立访客图例。
- 内容使用分布图，含总文档数和空间占比。

主要交互：打开日期范围控件、切换统计范围、查看趋势和分布。

QA 对照项：

- 当前唯一主数据源是有权限保护的 ops dashboard；响应缺少字段的卡片或图表必须 unavailable。
- 不使用设计稿静态数字，不扩大日期范围能力，不把审计/同步/备份结果塞进新导航。
- 日期控件在 loading、error 和 permission 状态下仍保留布局位置。
- 窄屏保持四卡可滚动或堆叠，趋势图不能压缩到无法读出图例。

布局类别：global。

可见结构：

### 3.8 回收站 / Recycle Bin — #/recycle

布局类别：global。

布局类别：module-map。

- 目标页面的权限/能力状态应在目标页显示，不在模块地图生成假结果。
- 窄屏保持编号、名称、说明和查看页面入口顺序清晰，tiles 可单列堆叠。

## 4. 窄视口验收原则

窄视口不是把桌面页面简单缩小。后续 QA 至少检查以下规则：

1. 核心页面标题、当前状态、主要操作和返回/发送入口始终可见且可操作。
2. 全局侧栏、知识空间侧栏、助手会话栏和上下文栏可以折叠、堆叠或进入抽屉，但不能覆盖主要内容或造成不可恢复的横向溢出。
3. 表格优先保证名称、状态、更新时间和单行操作可达；允许明确的横向滚动，不允许把状态列裁掉。
4. cards 和 module tiles 使用单列或双列重排，图表提供可读的最小宽度、图例和替代说明。
5. loading、empty、error、permission-denied、unavailable 状态在窄屏仍有完整文案和明确层级。
6. 键盘焦点、按钮禁用语义、文本对比度和状态颜色不依赖 hover 或仅颜色传达。
7. 视觉对照至少覆盖桌面 1181 × 1027 和一个窄视口；窄视口以主流程可完成、信息不重叠为通过条件。

## 5. M0 骨架与后续 QA 证据

app-v2 目录职责如下：

- AppV2.tsx：并行根边界和最小 hash 分发，不接管旧入口。
- routes.ts：十条路由的单一事实源，包含页面名称、布局类别、里程碑和页面组件。
- pages：十个页面占位模块，不复制旧 JSX。
- layouts：global、knowledge、assistant、module-map 布局边界。
- components：统一页面占位和状态面板。
- adapters：只定义边界、输入输出和能力状态；M0 不发请求。
- styles：app-v2 独立 token、全局样式和组件样式。
- types：路由、页面状态和 adapter contracts。
- fixtures/visual：仅视觉样本边界，M0 不提供业务 fixture。

后续每一页的视觉 QA 必须至少保留：

- 设计源和实际渲染视口；
- 页面根标题、section header 和主要布局关系；
- loading、empty、error、permission-denied、unavailable 的可见证据；
- 真实 API 能力与 disabled/unavailable 控件的对应关系；
