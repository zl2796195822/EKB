# EKB 灰度发布与上线计划 · M5-2

**版本**：v1.0  
**日期**：2026-08-08  
**负责人**：EKB 工程团队  
**适用里程碑**：M5-2（检索增强 + 安全加固 + 容量压测）

---

## 1. 发布阶段

### 阶段一：内部测试（第 1–2 天）

**目标用户**：内部研发团队，≤5 人（QA 工程师 + 后端负责人）

**开关条件**：
```bash
# 部署前在目标环境注入
export EKB_ROLLOUT_PHASE=internal
```
服务启动后通过 `GET /health` 确认 `rollout_phase: "internal"` 字段返回正确。

**验证清单**：
- 所有 P0/P1 功能用例（QA、Search、Upload、Auth）100% 通过
- 评估集首答准确率 ≥98%（使用 `eval/run_eval.py` 执行，结果写入 `eval/reports/`）
- QA 端点 P95 延迟 <3 s，Search 端点 P95 延迟 <50 ms（Locust 基准报告佐证）
- 无未豁免安全告警（`bandit -r apps/api` + `npm audit --audit-level=high` 零输出）
- Circuit Breaker 开路/半开/闭合状态机手动注入测试通过

**退出决策**：由 QA 负责人签字确认，方可进入阶段二。

---

### 阶段二：试点客户（第 3–7 天）

**目标用户**：1–3 个试点租户，要求覆盖至少一个高频写入租户和一个低频只读租户。

**开通方式**：
```bash
# 通过管理端点为指定租户开启 M5-2 功能集
POST /admin/tenants/{tenant_id}/features
Content-Type: application/json
{"features": ["m5_retrieval_v2", "m5_security_hardening"]}
```
同步将租户 ID 写入监控白名单，确保 Grafana 告警面板可按租户过滤。

**监控重点**：
- 每 6 小时巡检一次错误率（目标 <1%）
- 审计日志异常扫描：`grep "permission_denied\|403\|unauthorized" /var/log/ekb/audit.log`
- 用户反馈收集：在试点租户管理界面嵌入 NPS 快调，48 h 内回收

**退出准则**：
- 连续 3 天（72 h）无 P0/P1 故障
- 审计日志无异常越权记录（跨租户访问、特权接口未授权调用）
- 试点用户满意度反馈整体正向（NPS ≥ 0 或主观无重大投诉）

**退出决策**：由产品负责人 + 工程负责人联合确认，方可进入阶段三。

---

### 阶段三：全量上线（第 8 天起）

**变更方式**：
```bash
# 修改环境变量并滚动重启
export EKB_ROLLOUT_PHASE=ga
kubectl rollout restart deployment/ekb-api   # 或等效的 Docker Compose 重启
```

**退出准则（7 天滚动窗口达标后视为上线稳定）**：
- 服务可用性 ≥99.5%（基于 `/health` 探针，Prometheus `up` 指标）
- 所有端点错误率（5xx）<1%
- 备份恢复演练通过：从最新快照完整恢复至测试环境并通过冒烟测试
- 无 P0 故障复发

## 2. 回滚触发条件

下列任意条件满足，立即触发回滚，不等排期：

| 等级 | 触发条件 |
|------|----------|
| **P0 — 立即回滚** | 服务不可用（`/health` 连续 3 次 5xx）；数据损坏或跨租户数据泄露；认证/授权完全失效；QA P95 延迟 >10 s 超过 5 分钟 |
| **P0 — 立即回滚** | 错误率（5xx）>10% 持续超过 3 分钟 |
| **P1 — 30 min 内决策** | QA P95 延迟 3–10 s 持续超过 15 分钟；错误率 1%–10% 持续超过 10 分钟；Circuit Breaker 半开后持续开路 >10 min |
| **P1 — 30 min 内决策** | 审计日志出现批量异常越权记录（>5 条/分钟） |

> **P0 定义**：核心业务功能不可用，或存在安全/数据完整性风险，无可接受的降级方案。

## 3. 回滚操作步骤

```bash
# Step 1：确认当前版本及上一个稳定 tag
git log --oneline -5
# 记录当前 commit SHA，备用

# Step 2：切换至上一个稳定镜像版本
# Docker Compose 环境
docker compose pull ekb-api:stable
docker compose up -d ekb-api

# Step 3：回滚环境变量（如使用 .env）
sed -i 's/EKB_ROLLOUT_PHASE=.*/EKB_ROLLOUT_PHASE=stable/' .env
docker compose restart ekb-api

# Step 4：验证回滚成功
curl -sf http://localhost:8000/health | python3 -m json.tool
# 期望：{"status":"ok","rollout_phase":"stable"}

# Step 5：执行冒烟测试
python3 apps/api/tests/smoke_test.py --env staging

# Step 6：通知值班频道
# 在 Slack #ekb-oncall 发送：
# "[ROLLBACK] M5-2 已回滚至 stable，原因：<触发条件>，回滚时间：$(date -u)"

# Step 7：创建 P0/P1 事故记录
# 在项目管理工具中开单，填写：触发时间、影响范围、根因初判、跟进负责人
```

整个回滚操作目标完成时间：**P0 ≤15 分钟，P1 ≤30 分钟**。
