## 1. 测试分层

| 层级 | 目标 | 必测内容 |
|---|---|---|
| 单元测试 | 验证纯逻辑、规则和数据转换 | 权限判定、状态机、错误映射、切分规则 |
| 集成测试 | 验证 API、数据库、对象存储和 RAG 适配层 | 上传、入库、检索、问答、审计 |
| 端到端测试 | 验证真实用户旅程 | 登录、上传、检索、流式问答、反馈、拒绝越权 |
| 安全测试 | 验证租户隔离、出域和注入防护 | 越权、对象直链、提示注入、导出 |
| 性能测试 | 验证 M4 负载与延迟 | P95 延迟、吞吐、恢复时间、缓存命中率 |
| RAG 评估 | 验证可信问答质量 | 准确率、引用正确率、拒答率、幻觉率 |

## 2. 任务级 DoD

每个开发任务在完成前都必须满足：

1. 先写失败测试，再实现，再复测通过。
2. 测试用真实结构化数据，不只检查状态码或“服务能启动”。
3. 每个任务都有明确的输入、输出和断言。
4. 与权限、引用、审计、缓存相关的任务必须带负向用例。
5. UI 任务必须包含加载、空、失败、无权限和重试状态。
6. 任务必须填写并读取 Backlog 的 `Skill refs`；完成记录需要列出实际使用的规则和验证证据。

### 2.1 Skills 与测试证据

前端和浏览器流程使用本地 `playwright` skill，保存快照、截图或 trace 到 `output/playwright/`；UI 审查同时读取 `web-design-guidelines`。认证、上传、权限、租户隔离和外部模型调用使用 `security-best-practices`，改变信任边界时补充 `security-threat-model`。测试报告本身使用 `writing-guidelines` 检查术语、范围、证据和链接。Skills 只规定检查方法，测试门禁和 Spec 的验收值优先。

| 领域 | 必测项 | 证据 |
|---|---|---|
| 认证 | 登录、刷新、退出、过期、错误账号消息不泄露 | API 测试、日志抽样 |

## 5. 关键验收测试

### 5.1 M1 验收

- 上传一份脱敏 PDF，断言任务从 `PROCESSING` 进入 `READY`，chunk 数和引用数大于 0。
- 使用授权用户提问，断言 SSE 事件序列包含 `request -> retrieval -> token/citation -> done`。
- 使用 Stream v2，断言事件包含同一 `turn_id` 和严格递增 `seq`，并经过 `retrieval_started -> retrieval_completed -> generation_started -> delta/citation -> done`；heartbeat 不改变阶段。
- 在首个可见事件前调用 cancel，断言草稿恢复、无重复消息；在输出后调用 cancel，断言部分回答保留且终态为 `cancelled`。
- 注入重复、倒序和旧 turn 事件，断言客户端丢弃且 `qa_stream_protocol_errors` 可观测。
- 使用无依据问题，断言返回明确拒答而不是拼接虚构引用。
- 使用无权限用户，断言响应不泄露资源存在性。

### 5.2 M2 验收

- 换租户后，同一用户无法看到其他租户知识库、文档或会话。
- 修改 ACL 后，新请求立即受新权限约束，旧缓存失效。
- 客户租户无法通过直链获取未授权对象。

### 5.3 M4 验收

- 在冻结数据量和硬件上达到 NFR 目标。
- 压测报告包含 P95 延迟、吞吐、错误率、降级率和缓存命中率。
- 备份恢复演练能恢复业务库、对象存储和索引元数据。

## 6. 推荐命令形状

> 具体命令在实现时按实际技术栈冻结；以下为门禁形状，不写死尚未创建的项目脚本。

| 目的 | 命令形状 | 期望 |
|---|---|---|
| 单元测试 | `pytest tests/...` 或等价命令 | 全通过 |
| 集成测试 | `pytest tests/... -m integration` | 全通过 |
| 前端测试 | `npm test` / `pnpm test` / `vitest` | 相关用例通过 |
| E2E | `playwright test` | 通过主流程与错误路径 |
| Lint | `ruff check .` / `eslint .` | 0 错误 |
| 类型检查 | `mypy` / `tsc --noEmit` | 0 错误 |
| 压测 | `k6 run ...` | 达到门槛 |

## 7. 缺陷分级

| 级别 | 定义 | 是否阻塞发布 |
|---|---|---|
| P0 | 越权、数据泄露、严重错引、核心流程失败 | 是 |
| P1 | 影响核心体验或回退路径弱 | 条件阻塞，需书面豁免 |
| P2 | 局部缺陷，不影响主流程 | 否 |
| P3 | 细节改进或低风险瑕疵 | 否 |

## 8. 发布门禁

- [ ] P0 为 0。
- [ ] P1 有书面豁免和截止版本。
- [ ] 评估集、权限专项、安全专项和 E2E 证据齐全。
- [ ] 回滚方案和备份恢复演练通过。
- [ ] 文档、接口、数据模型和部署手册同步更新。
- [ ] Stream v2 的协议、迁移、状态机、取消、SLO、灰度和回滚证据齐全；M3 回放未被隐式纳入 M1。
- [ ] 每项变更记录 `Skill refs`、已读取文件、测试命令和可复核证据。
