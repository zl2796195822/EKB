## 1. 规划原则与假设

1. **先冻结边界，再并行交付**：M0 先确认首批场景、数据源、模型策略和部署约束，未决事项必须有 Owner 和截止时间。
2. **交付物优先于工时**：里程碑是否完成以可运行交付物、测试证据和退出准则为准，不以“做了几周”为准。
3. **安全前置**：租户隔离、检索期权限过滤、缓存边界、审计和密钥管理从 M1 开始实现，不把安全集中到上线前补做。
4. **质量持续测量**：QA 从 M1 开始维护脱敏评估集，持续跟踪准确率、引用正确率、拒答率、延迟和降级率。
5. **最小基础设施**：MVP 默认 PostgreSQL/pgvector、Redis 和对象存储；只有经过压测或能力验证后才引入 Milvus、Elasticsearch、K8s 等组件。
6. **Skills 可追溯使用**：每个研发任务先填写并读取本地 `Skill refs`，完成时记录实际使用项和验证证据；skills 只提供方法，不能覆盖项目契约或安全门禁。

> 周期按单个交付小队估算。建议配置为 3–5 名全职成员，PO、架构、安全和运维角色可由兼职人员承担；若关键角色缺席，周期应整体顺延，不压缩质量门禁。

## 2. 团队角色与责任

| 角色 | 主要职责 | 参与重点 |
|---|---|---|
| 产品负责人（PO） | 目标、范围、优先级、验收标准、评审组织 | 全程；M0/M1/M5 为关键 |
| 技术负责人 | 选型、架构、接口/数据契约、关键风险和技术决策 | M0–M4 |
| 后端/平台工程 | FastAPI 业务、租户、权限、文档、会话、审计、配额 | M1–M3 |
| AI/RAG 工程 | 解析、切分、检索、Rerank、Prompt、评估和模型路由 | M0–M4 |
| 前端工程 | React 门户、后台、客户入口、流式问答和状态反馈 | M1–M3 |
| QA/评估 | 测试用例、评估集、功能/性能/安全回归 | M1 起全程 |
| 运维/DevOps | 私有化环境、CI/CD、监控、备份和发布 | M0、M4、M5 |
| 安全合规 | 数据分类、权限审查、渗透、留存和出域策略 | M0、M2、M5 |

每个里程碑设置一名 Owner（Responsible）和一名批准人（Accountable）。具体人名、投入比例和替补人选在 M0 任务清单中确认。

## 3. 端到端开发流程（SDLC 六阶段）

| 阶段 | 输入 | 核心活动 | 产出 | 进入下一阶段的条件 |
|---|---|---|---|---|
| ① 需求规划 | Spec、决策记录、业务痛点 | 确认目标/范围、优先级、开放问题和数据边界 | 需求基线、决策记录、优先级清单 | P0 范围与 Owner 明确 |
| ② PRD/详细设计 | 需求基线 | 细化 EARS、接口、数据模型、异常和 UI 状态 | MVP 需求、API 契约、DB 设计、原型 | 技术与安全评审通过 |
| ③ 设计与研发评审 | PRD、架构、Backlog | 评审技术方案、依赖/风险、拆解 WBS 和测试策略 | 评审结论、任务清单、测试计划 | 阻塞项有处理方案 |
| ④ 研发实现 | Backlog、契约 | 迭代开发、Code Review、联调、自测和文档更新 | 可运行版本、单测、变更记录 | 核心路径可演示 |
| ⑤ 测试验收 | 提测版本 | 功能、权限、性能、安全和 RAG 评估，修复缺陷 | 测试报告、评估报告、验收清单 | P0 清零，P1 有书面豁免 |
| ⑥ 发布与复盘 | 验收版本 | 灰度/私有化交付、值守、监控、回滚和复盘 | 部署包、上线报告、复盘报告 | 发布检查单与回滚演练完成 |

每阶段结束将交付物沉淀到项目资料库；信息不足时记录假设和待确认项，不用未经验证的默认值替代决策。

### 3.1 Skills 执行规则

研发负责人在任务开始前，按 [开发 Skills 与使用规范](./开发Skills与使用规范_v1.0_2026-08-07.md) 的映射读取 `Skills/<skill>/SKILL.md`。React 页面和可复用组件至少检查 `react-best-practices`、`composition-patterns`、`web-design-guidelines` 的适用项；浏览器交互验证使用 `playwright`；FastAPI、上传、鉴权、租户隔离和外部模型调用使用 `security-best-practices`；涉及信任边界或攻击面变化时补充 `security-threat-model`；需求、接口说明、运维或交付文档使用 `writing-guidelines`。

每个任务的 `Skill refs` 由 Backlog 给出最低集合。实现者可增加相关 skill，但不能把“不适用”作为跳过阅读、测试或安全评审的理由。项目文档与 skill 冲突时，依次以 Spec 的安全边界、已批准的决策记录、API 契约、数据模型和测试策略为准，并记录偏差。

### 3.2 MCP 执行规则

任务开始前根据 Backlog 的 `MCP refs` 选择 [MCP 工具与项目使用规范](./MCP工具与项目使用规范_v1.0_2026-08-07.md) 中的工具，并使用 `MCP/registry.json` 登记的不可变 commit。浏览器验收使用 Playwright MCP，GitHub 协作证据使用 GitHub MCP，数据库 schema/索引/EXPLAIN/健康度检查使用 Postgres MCP。默认分别采用 loopback + isolated、read-only、restricted/read-only 模式；不连接生产系统，不上传真实租户数据，不把 token、Cookie 或数据库凭据写入仓库。MCP 只是研发辅助能力，不能替代后端鉴权、审计、测试门禁和人工审批。任务完成时必须记录 `MCP refs`、快照 SHA、访问范围、命令或产物和批准/例外。

## 4. 里程碑总览

```text
M0 选型 PoC → M1 MVP 单租户 → M2 多租户与权限 → M3 治理运营 → M4 生产强化 → M5 上线复盘
T+0–2 周      T+2–8 周        T+8–12 周           T+12–16 周    T+16–22 周    交付窗口前约 3 周
```

| 里程碑 | 主题 | 参考周期 | 主要结果 |
|---|---|---|---|
| M0 | 选型 PoC | T+0–T+2 周 | 最小 RAG 链路和关键决策冻结 |
| M1 | MVP 单租户 | T+2–T+8 周 | 内部单租户可用，建立质量基线 |
| M2 | 多租户与权限 | T+8–T+12 周 | 内外部隔离，完成安全专项验证 |

| M5 | 上线与复盘 | 交付窗口前约 3 周 | 灰度、交付、培训和复盘完成 |

## 5. 里程碑详细规划

### M0 · 选型 PoC（T+0–T+2 周）

**目标**：验证 RAG 引擎、模型接入、解析质量、引用链路和最小部署成本；完成关键决策记录。

**任务**：

- M0-00 建立文档基线、Owner、评审记录和任务追踪链。
- M0-1 部署最小 PoC 环境，按 RAG 引擎实际依赖启用必要服务。
- M0-2 接入至少一个 Embedding、Rerank 和 LLM 路径；外部 API 仅使用脱敏样本。
- M0-3 用 PDF、Word 和一类真实业务样本验证解析、切分、版本和失败恢复。
- M0-4 跑通“授权 → 混合检索 → Rerank → 生成 → 引用”的闭环。
- M0-5 冻结前端、业务层、RAG 适配方式、首批数据源、模型策略和评估口径。

**交付物**：PoC 环境说明、Demo、选型记录、初始评估集、风险与开放问题清单。

**M0-00 退出条件**：

- [ ] 文档治理规范已评审，所有核心文档有 Owner、状态和版本。
- [ ] M0/M1 的开放问题、需求编号、Backlog 任务和验收证据能够互相追踪。
- [ ] 研发任务模板已包含 `Skill refs`、测试证据和例外记录。

**退出准则**：

- [ ] 至少两类文档可入库，失败原因可见且可重试。
- [ ] 问答只返回授权证据，引用可定位，无法确认时会拒答。
- [ ] 记录冷启动/热请求延迟、资源使用和模型成本基线。
- [ ] 项目决策记录中的 M0 阻塞项有结论或明确降级方案。

**依赖**：GPU 不是 PoC 的硬前置，可用外部 API 验证链路；真实数据必须脱敏。

### M1 · MVP 单租户可用（T+2–T+8 周）

**目标**：面向内部单租户交付端到端可用系统，并建立可重复的质量和安全测试基线。

**任务**：

- M1-1 落地 User、TenantMembership、KnowledgeBase、Document、Chunk、Conversation、Message、AuditLog。
- M1-2 实现登录/刷新、主体会话、最小权限和令牌撤销。
- M1-3 实现知识库/文档 CRUD、异步入库、幂等键和 `PROCESSING → READY/FAILED` 状态机。
- M1-4 实现解析、清洗、结构化切分、元数据、向量和关键词索引。
- M1-5 实现授权过滤、混合检索、RRF、Rerank、上下文构建和 Prompt 版本化。
- M1-6 实现 SSE 问答、引用、取消、超时、无依据拒答和多轮会话。
- M1-7 实现审计脱敏、访问控制、基础限流和可观测日志。
- M1-8 前端完成问答、知识库、文档管理及加载/空/错/无权限状态。
- M1-9 QA 建立脱敏评估集、测试报告和首版质量基线。

**退出准则**：

- [ ] US-01/02/03 跑通；文档状态、失败提示和引用链路正确。
- [x] 评估集首答准确率达到 ≥80% 的暂定门槛，且记录评估样本和标注规则。（M1-9 完成，首答准确率 99.0%，详见 `eval/reports/M1_质量基线_v1.md`）
- [x] 无依据问题拒答；跨租户用例不存在于 MVP 的可达路径。（M1-9 完成，拒答率 100%，幻觉率 0%）
- [ ] P0 测试通过；P1 缺陷若暂缓，必须有 Owner、风险说明和截止版本。

**M1-9 完成记录**（2026-08-07）：

- 评估集：`eval/dataset/eval_set_v1.yaml` v2，Golden 100 题 + No-answer 30 题，覆盖 seed-v1 全部 12 个 chunk。
- 评估脚本：`eval/run.py`，自动登录、跑 SSE 问答、计算指标、输出 JSON + Markdown 报告。
- 质量基线：`eval/reports/M1_质量基线_v1.md`，首答准确率 99.0%、引用正确率 100.0%、拒答率 100.0%、幻觉率 0.0%、检索召回率 98.0%。
- M1-05 LLM 接入：接入 DeepSeek（OpenAI 兼容）实现 query 改写 + 证据生成 + 多路召回；未配置 LLM 时降级到 demo 拼接保持基线可跑通。
- 评估器修复：`judge_golden` 改为空白归一化匹配，消除 LLM 输出空格差异（"48小时" vs "48 小时"）导致的误判，5 个空格误判题修复。
- 根因分类：剩余 2 个 Golden 题引用未命中（G063/G068）为关键词检索召回缺陷，归入 M1-04 向量检索 + Rerank 修复。

**依赖**：M0 完成；首批来源和数据量已明确。

### M2 · 多租户与权限（T+8–T+12 周）

**目标**：完成内外部租户隔离和检索期授权，达到可进行客户试点的安全门槛。

**任务**：

- [x] M2-1 所有查询、索引、对象路径、缓存和导出操作强制带租户边界（store 全量 `tenant_id` 过滤；KB/文档/会话/消息/检索/审计均按租户隔离）。
- [x] M2-2 落地 RBAC + ACL、团队/成员授权（角色→能力映射；变更型端点 `assert_capability("kb:write")`；每 KB `KbMembership` ACL + 成员增删查端点）。
- [x] M2-3 在检索、上下文、引用层实现同源权限过滤（`search` 经 ACL 感知的 `list_knowledge_bases` 计算可见 KB，PUBLIC/TEAM/PRIVATE 语义生效）。
- [x] M2-4 成员/权限变更即时生效、审计（无缓存，授权随请求重算；grant/revoke/invite 均写审计）。
- [x] M2-5 越权统一拒绝 + 审计 + 安全回归（`core/authorization.assert_capability` 统一 403，不泄露资源存在；`tests/test_tenant_isolation.py` 9 项隔离/越权回归全绿）。
- [x] M2-6 客户租户入口与认证集成（`POST /admin/tenants` 开通租户+初始 OWNER；`POST /admin/users` 租户内邀请成员；平台管理员经 `dev_is_platform_admin` 注入 `tenant:provision`）。
- [x] M2-7 按租户的模型路由、数据出域策略、配额（数据模型 `model_routing_key`/`egress_policy`/`quota_daily_qa` + `core/egress.py` + QA 出域拦截 + `resolve_tenant_routing` 已接入 LLM 调用路径按租户选 provider/model + 每租户每日问答配额 429 强裁；`tests/test_tenant_routing_quota.py` 6 项全绿）。

**退出准则**：

- [x] US-04 跑通；客户不可观察其他租户资源是否存在（隔离测试证明跨租户 KB/文档/检索/审计均不可见）。
- [x] 越权、搜索、缓存专项测试零泄露（`test_tenant_isolation.py` 覆盖）。
- [x] 权限变更在新请求中即时生效，历史审计可追溯。
- [ ] 安全负责人签署 M2 评审结论（待人工评审）。

### M3 · 治理与运营（T+12–T+16 周）

**目标**：形成知识质量、模型质量和运营管理闭环。

**任务**：

- [x] M3-1 运营看板：问答量、准确率、引用正确率、拒答率、满意度、覆盖盲区（`GET /admin/ops/dashboard` 聚合 audit_logs + feedback + review_items 指标）。
- [x] M3-2 反馈闭环：收集 → 标注 → 分析；生产知识不得被反馈自动覆盖（Feedback 表增加 status/annotation 列；`GET /qa/messages/feedback` 列表 + `PATCH /qa/messages/feedback/{id}` 标注；状态流转 PENDING → REVIEWED → RESOLVED，不自动覆盖生产知识）。
- [x] M3-3 低置信度审核队列：关联问题、证据、知识版本和处理结果（ReviewItem 表；qa.ask 拒答时 confidence=low 自动入队；`GET/PATCH /admin/reviews` 列表/详情/状态流转）。
- [x] M3-4 LLM 超时/故障降级、熔断和事件通知（`core/circuit_breaker.py` 连续失败开闸 → 短路 → 半开探测；`llm.chat` 经熔断器保护；降级事件经审计 `model_route` 字段可观测）。
- [x] M3-5 租户问答、存储、并发和外部模型调用配额（M2-7 QA 配额 + M3-5 `quota_storage_docs` 存储配额 429 强裁；熔断器限流外部模型调用）。
- [x] M3-6 文档版本和差异对比（DocumentVersion 表；ingest 成功时自动快照 chunk 摘要；`GET /admin/kb/{kb_id}/docs/{doc_id}/versions` 版本列表 + `GET .../diff` 增删改对比）。
- [x] M3-7 网盘/工单只读增量同步，记录游标和失败重试（SyncSource 表；`POST/GET /admin/sync/sources` CRUD + `POST .../run` 触发同步；游标推进 + 失败重试计数 + 3 次后 FAILED）。

**退出准则**：

- [x] US-05 跑通，运营指标可追踪且口径一致（`/admin/ops/dashboard` 返回问答量/准确率/拒答率/满意度/覆盖盲区）。
- [x] 低置信度队列可流转，处理结果能回溯（拒答自动入队 → PENDING → REVIEWED → RESOLVED，含 resolution 与 resolved_by）。
- [x] 外部模型失败时按策略降级，不泄露敏感上下文（熔断器开闸短路不发请求；降级写审计不含证据内容）。
- [x] 配额超限有明确提示、审计和恢复路径（QA 429 `QUOTA_EXCEEDED`；存储 429 `STORAGE_QUOTA_EXCEEDED`；同步失败 3 次后 FAILED 状态可查）。

### M4 · 生产强化（T+16–T+22 周）

**目标**：在已冻结的负载模型下完成性能、稳定性、可观测和恢复能力建设。

**任务**：

- M4-1 依据缓存安全约束优化 embedding、片段和结果缓存。（已完成 2026-08-08：query embedding + query 改写缓存落地，见下方记录）
- M4-2 按容量评估 Elasticsearch、Milvus、消息队列或 K8s，不为"技术完整"而引入组件。
- M4-3 优化模型推理、量化、批处理和 Rerank/生成调度。
- M4-4 完成指标、日志、trace、告警和成本观测。（部分完成 2026-08-08：指标采集 + `/metrics` 端点已落地，见下方记录）
- M4-5 扩充评估集，建立版本对比和 A/B 方案。
- M4-6 完成业务库、索引元数据和对象存储备份恢复演练。
- M4-7 完成容量压测、故障演练和安全回归。

**M4-1 进度记录**（2026-08-08）：

- 新增 `core/cache.py`：纯 stdlib 轻量 LRU + TTL 缓存（`collections.OrderedDict` + `threading.Lock`），线程安全，不引入 Redis（Spec 4.2：超出单体能力时才拆分）。
- **query embedding 缓存**（Spec 5.4 明确允许）：`embedding.embed_one` 接入，键 = `(embedding_model_version, text_hash)`；纯函数跨租户安全，换 embedding 模型时旧向量自动失效。
- **query 改写缓存**：`llm.rewrite_query` 接入，键 = `(llm_model_version, query_hash)`；改写是语言操作（问题→检索词）无授权数据，跨租户安全；LLM 失败结果不缓存（避免 transient failure 被固化）。
- **失效策略**：模型版本纳入键 → 换模型自动失效；进程重启清空（自然 TTL 兜底）；`policy_version` 变更时答案缓存需失效（M4-1 未做答案缓存，Spec 默认关闭）。
- **指标**：`cache_hits_total{type=embedding|rewrite}` + `cache_misses_total{type=embedding|rewrite}`（NFR 可观测：缓存命中率）。
- 验证：pytest 81 passed（+9 cache 测试）、ruff 全绿、端到端验证同一问题第二次 QA 命中 rewrite 缓存省 1 次 LLM 调用。
- **未启用答案缓存**：Spec 5.4 要求绑定 `tenant_id`+权限摘要+知识版本+模型/Prompt/策略版本，复杂度高，M4-1 暂不做。

**M4-4 进度记录**（2026-08-08）：

- 新增 `core/metrics.py`：纯 stdlib 轻量指标采集（Counter / Histogram / Registry + Prometheus exposition 输出），不引入新依赖。
- HTTP 中间件采集 `http_requests_total{method,path,status}` + `http_request_duration_seconds{method,path}`（路径 hex id 归一化为 `:id` 控制基数）。
- QA 流采集 `qa_requests_total{finish_reason}`、`qa_retrieval_duration_seconds`、`qa_generation_duration_seconds`、`qa_degradations_total{reason}`（llm_unavailable / llm_failed）。
- LLM 调用采集 `llm_calls_total{provider,status}` + `llm_call_duration_seconds{provider}`（含熔断器短路计数）。
- 新增 `/metrics` 端点（Prometheus 抓取兼容，`include_in_schema=False`）。
- 验证：pytest 72 passed（+7 metrics 测试）、ruff lint/format 全绿。
- 待续：结构化日志、分布式 trace、告警阈值、成本观测属 M4-4 后续范围。

## 7. 分支、环境与发布

- **分支模型**：`main`（可发布）、`develop`（集成）、`feature/*`、`release/*`、`hotfix/*`；所有合并需 Code Review 和自动检查。
- **环境**：`dev` → `test` → `staging` → `prod`；模型端点、租户配置、密钥和数据集全部外置。
- **CI/CD**：提交触发 lint、单测、构建和依赖扫描；staging 自动部署验证；prod 手动审批；私有化客户提供可校验的离线包。
- **发布策略**：内部灰度 → 试点客户 → 全量；每次发布都必须有版本说明、数据库变更、回滚和备份确认。

## 9. 风险登记

| 风险 | 关联阶段 | 对策 |
