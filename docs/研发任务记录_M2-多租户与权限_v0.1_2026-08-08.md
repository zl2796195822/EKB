## 1. 本次完成项

### M2-1 租户边界强制
- store 层所有查询（KB/文档/会话/消息/检索/审计）均已按 `tenant_id` 过滤，属既有基础；本次以 `tests/test_tenant_isolation.py` 建立**跨租户零泄露**安全回归，证明既有隔离成立。

### M2-2 RBAC + 每知识库 ACL + 团队授权
- 新增 `core/authorization.py`：能力常量（`kb:read/write`、`qa:ask`、`audit:read`、`tenant:provision`）、`ROLE_CAPABILITIES`（OWNER/ADMIN 全量、MEMBER 只读+问答+审计、CUSTOMER 仅问答）、`assert_capability`（统一 403）、`assert_kb_manager`。
- 变更型端点（kb 的 create/update/delete/upload/retry/delete-doc、admin 审计）统一 `assert_capability("kb:write")`，MEMBER 越权写 → 403。
- 新增 `KbMembership` 模型与 store 方法 `grant/revoke/list/get_kb_membership`；创建 KB 自动授予创建者 OWNER 成员。
- `list_knowledge_bases` / `get_knowledge_base` 按可见性过滤：**PUBLIC** 全租户、**TEAM** 同租户、**PRIVATE** 仅成员或租户 OWNER/ADMIN。
- `routers/kb.py` 增加 `GET/POST /kb/{kb_id}/members`、`DELETE /kb/{kb_id}/members/{user_id}`，需 KB OWNER/ADMIN 成员 + `kb:write`。

### M2-3 检索同源过滤
- `search` 与 `qa/ask` 均经 ACL 感知的 `list_knowledge_bases` 计算可见 KB；检索 SQL 已按 `tenant_id` 过滤，故同源过滤在检索/上下文/引用层自然生效。

### M2-4 即时生效 + 审计
- 无缓存，授权随每个请求重算 → 成员/权限变更即时生效；grant/revoke/invite/provision 均写审计日志。

### M2-5 统一拒绝 + 安全回归
- 越权统一 403（`PERMISSION_DENIED`），不泄露资源是否存在；`tests/test_tenant_isolation.py` 9 项全绿（跨租户隔离、MEMBER 写拒绝、非 KB 管理员不可授权、ACL 授权后可见、租户开通隔离、非平台管理员不可开通、出域拦截）。

### M2-6 租户开通与成员邀请
- `config.dev_is_platform_admin`（默认 true，生产应 false）注入 `platform_role=PLATFORM_ADMIN` 与 `tenant:provision` 能力。
- `POST /admin/tenants` 开通租户 + 初始 OWNER（口令 PBKDF2 哈希）；`GET /admin/tenants` 列出租户。
- `POST /admin/users` 在调用方租户内邀请成员（任意角色），需 `kb:write`。

### M2-7 租户模型路由 + 出域策略 + 配额（完结）
- `Tenant` 模型增加 `model_routing_key` / `egress_policy` / `quota_daily_qa`；`core/egress.py` 提供 `EgressPolicy`、`assert_egress_allowed`、`TenantRoute`、`resolve_tenant_routing`。
- **出域拦截**：`qa/ask` 入口调用 `assert_egress_allowed`：`egress_policy=deny` 的租户问答 → 403（已测）。
- **模型路由接入 LLM 调用路径**（此前为待办，本次收尾）：
  - `resolve_tenant_routing(auth, settings, model_routing_key=...)` 解析出 `TenantRoute(provider_name, model)`，优先级：① `EKB_TENANT_MODEL_ROUTING[tenant_id]`（租户级直配）② `EKB_MODEL_ROUTES[tenant.model_routing_key]`（基于路由键的运营配置）③ 默认（settings 顺序）。
  - `llm.chat` 支持 `provider_name` + `model` 覆盖；`rewrite_query` 与 `generate_answer` 均接收 `route`；`retrieval.retrieve` 与 `qa._retrieve_and_generate`/`_generate` 透传 route。即检索改写与最终生成都按租户路由选 provider/model。
  - `qa.ask` 审计 `metadata.model_route` 记录本次所用路由（观测性，已测为 `default` 当未配置时）。
- **每租户每日问答配额**：
  - `Tenant.quota_daily_qa`（0 = 不限）；新增 `tenant_daily_usage` 表（按自然日重置计数）。
  - `store.check_and_increment_qa_quota(tenant_id)` 原子校验+计数：`qa/ask` 入口超额 → 429 `QUOTA_EXCEEDED`（不进入流式生成）。
  - `POST /admin/tenants` 接受 `quota_daily_qa`；`TenantCreate`/`TenantResponse` 携带该字段；`GET /admin/tenants` 列表返回。

## 5. 附注：M2-7 修复记录（配额整型脏数据回归）
- **现象**：接入配额后，dev 账号（及历史租户）每次 `/qa/ask` 返回 500 `INTERNAL_ERROR`；评估全部 500。
- **根因**：`_migrate_tenant_columns` 对三列统一追加 `DEFAULT 'default'`，把字符串 `'default'` 写进了整型列 `quota_daily_qa`（SQLite 类型亲和宽松，未报错）；`check_and_increment_qa_quota` 比较 `quota <= 0` 时 `str <= int` 抛 `TypeError`。冒烟仅覆盖"新开租户（quota=1 整型）"路径，未触发种子 dev 租户的脏数据分支，故漏检。
- **修复**：
  1. `core/db.py` 迁移改为逐列正确缺省（model_routing_key→`'default'`、egress_policy→`'allow'`、quota_daily_qa→`0`）。
  2. `store.py` 新增 `_as_int` 容错转换，配额比较与计数均经 `_as_int(...)` 兜底，杜绝脏数据 500。
  3. 修复 dev 库既有两行 `quota_daily_qa='default'` 脏数据（置 0）。
- **教训**：对 SQLite 列迁移，整型列绝对不可用字符串缺省；且冒烟需同时覆盖"新写入整型"与"历史/种子行"两条路径。
