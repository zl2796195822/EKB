## 1. 设计目标与原则

### 1.1 产品约束

EKB 同时服务内部员工和外部客户，包含问答、文档、检索、权限、审计和运营等高密度任务。界面必须优先保证可理解、可复核和可控，而不是追求装饰性展示。

- **信任优先**：明确来源、更新时间、权限和系统状态，不把模型输出伪装成确定事实。
- **高效工作**：搜索、筛选、批量操作和键盘路径优先；减少无必要的页面跳转。
- **边界可见**：租户、知识库、可见性和角色在关键操作处持续可见。
- **状态完整**：每个核心页面都设计加载、空数据、错误、无权限、处理中和成功状态。
- **克制动效**：动效只用于流式输出、状态反馈和层级过渡；全局遵守 `prefers-reduced-motion`。
- **一致性优先**：采用一套组件和 token；参考技能只提供方法或单个素材，不混用多套设计语言。

### 1.2 设计读法

> 企业级知识库产品 UI：专业、安静、信息密度适中；浅色为默认，深色为可选；以引用、权限和状态为核心视觉表达。

### 1.3 设计旋钮

| 旋钮 | 建议值 | 说明 |
|---|---:|---|
| 布局实验性 | 3–4 / 10 | 后台以可预测和高效为先 |
| 动效强度 | 2–3 / 10 | 仅功能性微动效；门面页可局部提高 |
| 信息密度 | 5–6 / 10 | 表格和检索结果需要高密度，但保留可读留白 |

## 2. 技能库的使用边界

`EKB/Skills/` 是设计与实现参考资料，不是产品运行时依赖。前端任务开始前必须读取 Backlog 的 `Skill refs` 及对应的本地 `SKILL.md`；它们的输出必须落入项目自己的设计系统和代码仓库，并经过许可证、可访问性和性能检查。

| 技能库 | 用途 | 使用边界 |
|---|---|---|
| impeccable-main | 设计系统、页面规划和质量检查 | 作为主流程；命令和规则以仓库实际版本为准 |
| anthropics-skills | 视觉取舍、主题和 Web 测试方法 | 作为方法参考，具体实现由项目代码决定 |
| taste-skill | Anti-slop 和风格约束 | 用于减少模板化视觉，不替代可用性测试 |
| react-bits | React 动效和交互参考 | 只挑选必要组件，检查包体积和可访问性 |
| galaxy | CSS 微组件参考 | 片段需重写为项目组件，不直接复制未知依赖 |
| gsap-skills-main | 复杂时间线和性能方法 | 只有 CSS/原生动画不足时使用 |
| mengto-skills | 企业级布局和交互灵感 | 只作灵感，不直接复制品牌、文案或资源 |
| react-best-practices | React 性能、数据获取、重渲染和包体积 | 所有 React 实现与性能评审的最低参考；不将 Next.js 专用规则直接套入 Vite |
| composition-patterns | 可复用组件 API、状态上提和组合模式 | 组件出现布尔 props 膨胀、共享状态或复用需求时使用 |
| web-design-guidelines | 可访问性、表单、动效、响应式与交互审查 | UI 代码评审前读取；其上游规则可更新，项目基线与 WCAG 要求仍优先 |
| playwright | 真实浏览器交互、截图和问题复现 | 关键流程、权限态、错误态和响应式验证使用；产物放入工程约定的测试输出目录 |
| writing-guidelines | 页面文案、空状态、错误提示和设计说明审查 | 审查文案，不替代产品术语表、合规文案和 API 错误码 |

> 第三方技能、组件和插件的许可证以各自目录中的 LICENSE 和固定版本为准。当前 `web-design-guidelines` 与 `writing-guidelines` 的上游仓库根级许可证未声明，二者只可作内部参考；任何复制、改写后分发或随交付物传播的内容都需法务确认。详见 [开发 Skills 与使用规范](./开发Skills与使用规范_v1.0_2026-08-07.md)。

## 3. 设计系统基线

使用 `PRODUCT.md` 记录产品定位、用户和语气，使用 `DESIGN.md` 记录 token、组件和交互规则。二者在前端工程中落盘后，才作为项目唯一事实来源；本章的值是候选初稿。

### 3.1 色彩

| 角色 | 候选值 | 使用规则 |
|---|---|---|
| Primary | `oklch(55% 0.12 230)` 附近的蓝青色 | 主要操作、链接和焦点；最终值需做对比度测试 |
| Accent | `oklch(65% 0.10 175)` 附近的青绿色 | 辅助状态和少量强调，不作为大面积背景 |
| 页面底色 | `oklch(98% 0.004 250)` 附近的暖灰 | 长时间阅读场景 |
| 正文 | `oklch(30% 0.02 250)` 附近的深色 | 正文、标题和重要数据 |
| 次要文字 | `oklch(55% 0.015 250)` 附近的灰色 | 元信息、帮助文案；不能承担唯一信息 |
| 语义色 | 成功/警告/错误各一套 | 同时配合图标、文字或形状，不能只靠颜色表达 |

所有颜色必须在浅色和深色主题下通过 WCAG AA 对比度验证。不要使用紫色渐变、玻璃拟态或大面积装饰背景来表达“AI 感”。

### 3.2 字体与排版

- 中文正文/UI：项目自托管的思源黑体、HarmonyOS Sans 或等价字体，避免依赖不稳定的远程字体。
- 数据、工单号、型号和代码：使用 JetBrains Mono、Noto Sans Mono 或系统等宽字体。
- 标题、正文、辅助文本、表格数字和代码块定义固定字号/行高/字重阶梯；避免同一页面出现过多字重。
- 关键数字和时间使用等宽数字，长文档引用保证段落行宽和锚点稳定。

### 3.3 组件与交互底座

- React + TypeScript；组件底座候选为 shadcn/ui + Tailwind，最终以 M0 技术评审为准。
- 图标统一一套（例如 Lucide）；状态颜色、图标、文案三者同时表达。
- 所有表格、弹窗、下拉菜单、分页、筛选器和上传组件提供键盘操作、焦点管理和可读的错误提示。
- 组件 API 不暴露租户绕过能力；权限判断来自后端返回的有效能力集合。

## 4. 信息架构与页面清单

### 4.1 通用外壳（App Shell）

顶栏显示当前租户、全局搜索、通知、帮助和用户菜单；侧边栏按角色隐藏无权功能，但页面访问仍由后端鉴权；内容区提供面包屑、页面标题、上下文操作和响应式布局。

### 4.2 核心页面

| 页面 | 关联需求 | 信息重点 | 必备状态 |
|---|---|---|---|
| 登录/租户入口 | FR-AC-01、认证 | 选择或识别租户、登录方式和安全提示 | 加载、失败、锁定、SSO 跳转 |
| AI 问答 | `FR-QA-01`–`FR-QA-07`、`FR-SE-01` | 问题、答案、证据、置信度、反馈和会话 | 空会话、流式、取消、超时、无依据、失败 |
| 知识库列表 | `FR-KB-01`、`FR-AC-02` | 知识库、可见性、角色、更新时间和成员数 | 空、无权限、创建中、删除确认 |
| 文档管理 | `FR-KB-01`、`FR-KB-03`、`FR-KB-05`、`FR-KB-06` | 上传、批量操作、版本、入库状态和失败原因 | 上传中、处理中、成功、失败、重试、无权限 |
| 检索/搜索结果 | `FR-SE-01`、`FR-SE-02` | 命中高亮、来源、标签、时间、权限边界 | 无结果、过滤后为空、加载、失败 |
| 会话历史 | `FR-QA-04` | 会话列表、标题、更新时间和继续追问 | 空、归档、删除确认、加载 |
| 成员与权限 | `FR-AC-01`–`FR-AC-04` | 租户成员、团队、角色、显式授权和过期时间 | 无权限、保存中、冲突、越权拒绝 |
| 运营看板 | `FR-OP-02` | 问答量、准确率、引用正确率、拒答率和低置信度队列 | 无数据、数据延迟、筛选后为空 |
| 模型与策略配置 | `FR-OP-03`、`FR-OP-04` | 模型路由、数据出域、超时、降级和配额 | 未配置、测试连接、保存失败、审计提示 |
| 审计日志 | `FR-OP-01` | 操作者、动作、对象、结果、trace_id 和时间 | 脱敏、分页、导出审批、无结果 |
| 客户租户门户 | `FR-AC-01`、`FR-QA-05` | 品牌壳、授权知识和联系支持入口 | 仅显示本租户状态 |

### 4.3 关键交互规范

#### AI 问答与流式输出

- SSE 事件通过 `fetch` 或等价流式客户端接收，先写入局部消息缓冲，再按 `requestAnimationFrame` 批量更新 React 状态；不直接绕过框架修改 DOM，避免状态、无障碍树和并发渲染不一致。
- 流式期间显示停止按钮、连接状态和已生成内容；网络断开后允许重试或查看部分结果。
- 回答完成后渲染 Markdown，并把引用绑定到文档版本、章节和稳定锚点；无法定位时显示降级来源信息。

#### 权限与可信表达

- 当前租户、知识库可见性和角色在上传、分享、检索、问答和导出操作附近可见。
- 越权操作只显示统一的权限错误，不泄露资源名称、数量或存在性。
- 低置信度、模型降级、数据延迟和索引处理中必须使用明确文案，不以装饰性动画掩盖状态。

#### 无障碍与响应式

- 目标为 WCAG 2.1 AA 或更高：键盘可达、可见焦点、语义 HTML、正确的 aria 关系、读屏可读的流式状态。
- 关键表格在窄屏下提供列隐藏、横向滚动或卡片化降级；问答内容在移动端保持引用可展开。
- `prefers-reduced-motion` 开启时，流式和过渡动画降级为即时状态切换。

## 5. 设计与实现工作流

```text
① 读取技能与任务边界
   读取 Backlog 的 Skill refs、相关 SKILL.md、Spec、API 契约和安全要求

② 设计系统
   初始化 PRODUCT.md / DESIGN.md，冻结 token、组件、文案和状态规则

③ 页面建模
   按 Spec 需求编号梳理主流程、异常流程、权限边界和响应式行为

④ 实现
   React 组件 → API 契约 → 流式/上传/权限状态 → 错误与空状态

⑤ 校验
   Web 设计准则、无障碍、响应式、视觉回归、Playwright 交互、流式性能、权限行为和真实数据走查

⑥ 迭代与留痕
   只在有用户反馈或可测量问题时调整动效、密度和信息层级
   记录实际使用的 skills、测试证据和与 skill 不同的项目决策
```

### 5.1 AI 问答页示例

1. 先定义问题输入、检索范围、流式状态、引用结构、拒答和错误状态。
2. 用设计 token 建立输入区、消息区、证据卡片、反馈和会话列表。
3. 接入 SSE，使用批量状态更新；验证停止、重试、超时和部分结果保留。
4. 用真实脱敏文档验证引用跳转、权限隐藏和长答案性能。
5. 通过无障碍、视觉回归和权限专项测试后，再考虑单点装饰性动效。

## 6. 落地清单

1. 在前端工程根目录初始化 `PRODUCT.md` 和 `DESIGN.md`，并记录决策日期和负责人。
2. 冻结 React、组件底座、字体、图标、主题和 token；所有页面禁止自行创建同义 token。
3. 按 M1 顺序实现问答、知识库、文档管理，再实现检索结果和会话历史。
4. 为每页补齐加载、空、错、无权限、处理中、成功和重试状态，并绑定接口错误码。
5. 建立 Storybook 或等价组件预览、视觉回归和键盘/读屏检查。
6. 动效只服务于状态反馈；上线前检查 `prefers-reduced-motion`、包体积和低端设备帧率。
7. 每个页面关联 Spec 需求编号、测试用例、截图证据和实际使用的 `Skill refs`，评审后再进入下一页。

---

## 7. 合规与交付注意事项

- 技能库、组件库、字体和插件按实际导入版本逐项核验许可证；需要 attribution 的内容保留归属信息。
- 不将客户名称、文档内容、服务器地址、账号、口令、API Key 或生产截图放入公开设计稿。
- 设计稿和截图使用脱敏数据；真实租户、权限和审计信息只在受控环境验证。
- UI 不能替代后端安全控制；任何“隐藏菜单”“禁用按钮”都必须由 API 层再次拒绝。
