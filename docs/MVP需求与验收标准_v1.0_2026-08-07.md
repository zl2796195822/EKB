## 1. MVP 范围

### 1.1 MVP 必须交付

| 范围 | 说明 | 关联需求 | 目标里程碑 |
|---|---|---|---|
| 内部单租户知识问答 | 登录后在授权知识库内发起流式问答，返回答案、引用和拒答状态；支持 Stream v2 阶段、取消和旧流隔离 | `FR-QA-01`–`FR-QA-04`、`FR-QA-08`、`FR-SE-01` | M1/M2 |
| 文档上传与入库 | 支持 M0 冻结的首批格式，完成解析、切分、索引、失败可见和重试 | `FR-KB-01`、`FR-KB-02`、`FR-KB-03`、`FR-KB-05` | M1 |
| 基础权限与审计 | 用户、租户、知识库角色、文档操作和问答审计 | `FR-AC-01`、`FR-AC-02`、`FR-OP-01` | M1/M2 |
| 检索期授权 | 检索、上下文构建、引用、缓存都不得包含未授权数据 | `FR-QA-05`、`FR-AC-01`–`FR-AC-04` | M2 |
| 客户租户入口 | 外部客户只能访问本租户授权知识，统一拒绝越权请求 | `FR-AC-01`、`FR-QA-05` | M2 |
| 基础质量评估 | 建立脱敏评估集，输出准确率、引用正确率、拒答率和延迟基线 | G2、G4、G5、NFR | M1 起 |

### 1.2 MVP 不做

| 非目标 | 说明 | 后续处理 |
|---|---|---|
| 源系统写回 | 工单、网盘、Wiki 均先只读同步或手动导入 | 如业务需要，拆出 M3+ 独立需求 |
| 模型训练/微调 | v1.0 只做模型路由、Prompt、检索和评估 | 评估数据积累后再立项 |
| 开放域闲聊 | 无证据时必须拒答 | 不进入 EKB 产品边界 |
| Kubernetes/Milvus/Elasticsearch 默认部署 | 不作为 MVP 默认依赖 | M4 按容量或性能验证触发 |
| 自动用反馈改生产知识 | 反馈只进入审核与质量分析 | M3 建治理闭环 |

## 2. 用户旅程与验收

### US-01 内部问答

**前置条件**：用户属于租户，拥有至少一个知识库 `VIEWER` 权限；知识库内存在 `READY` 文档。  
**成功路径**：用户提问 → 后端鉴权 → 检索授权片段 → 重排 → 生成 → SSE 返回答案 → 展示引用 → 记录审计。  
**验收标准**：

| 编号 | 验收点 | 通过标准 |
|---|---|---|
| AC-US01-01 | 流式响应 | 首个有效事件、检索状态、回答片段、引用和结束事件按契约返回 |
| AC-US01-02 | 引用可复核 | 每条引用包含文档名、章节路径、文档版本、chunk 定位和更新时间 |
| AC-US01-03 | 无依据拒答 | 证据不足时不编造，返回明确拒答和可尝试的检索方向 |
| AC-US01-04 | 多轮权限 | 同一会话每轮重新计算权限，权限变更后新请求即时生效 |
| AC-US01-05 | 审计 | 问答、模型路由、引用、拒答和错误都有 `trace_id` |
| AC-US01-06 | 流阶段 | UI 能区分排队、检索、生成、取消、完成、拒答、超时和失败，阶段不会因旧流事件回退 |
| AC-US01-07 | 轮次隔离 | 每次问答有服务端 `turn_id` 和递增 `seq`；重复、倒序或旧 turn 事件不改变当前消息 |
| AC-US01-08 | 取消恢复 | 首个可见输出前取消恢复草稿且不重复显示；已有输出后保留部分答案并标记“已取消” |
| AC-US01-09 | 引用一致 | 引用直接来自 SSE payload，与本轮授权上下文一致；问答主链路不依赖独立预搜索结果 |

### US-02 案例沉淀

**前置条件**：知识管理员拥有目标知识库 `EDITOR` 或以上权限。  
**成功路径**：上传文档 → 返回入库任务 → 解析切分 → 写入对象存储和索引 → 文档状态变为 `READY` → 可被授权问答引用。  
**验收标准**：

| 编号 | 验收点 | 通过标准 |
|---|---|---|
| AC-US02-01 | 格式支持 | M0 冻结格式至少覆盖 PDF、Word 和一类真实业务样本 |
| AC-US02-02 | 幂等上传 | 相同 `Idempotency-Key` 不重复创建文档和任务 |
| AC-US02-03 | 失败可恢复 | 解析失败保留状态、原因、`trace_id` 和重试入口 |
| AC-US02-04 | 状态隔离 | `PROCESSING`、`FAILED`、`DELETED` 文档不参与检索 |
| AC-US02-05 | 版本追踪 | 文档 checksum、来源、版本和更新时间可审计 |

### US-03 新人学习

**前置条件**：用户已登录，拥有租户内授权知识库只读权限。  
**验收标准**：

| 编号 | 验收点 | 通过标准 |
|---|---|---|
| AC-US03-01 | 会话连续 | 用户可查看历史会话并继续追问 |
| AC-US03-02 | 上下文受控 | 历史上下文只作为问题理解辅助，不扩大检索权限 |
| AC-US03-03 | 低信任提示 | 低置信度或数据过期时 UI 明确展示状态 |

### US-04 客户租户服务

**前置条件**：客户用户属于外部租户，认证方式按 OQ-006 冻结。  
**验收标准**：

| 编号 | 验收点 | 通过标准 |
|---|---|---|
| AC-US04-01 | 租户隔离 | 客户无法搜索、引用、导出、猜测其他租户资源 |
| AC-US04-02 | 统一拒绝 | 越权响应不泄露资源是否存在、名称或数量 |
| AC-US04-03 | 对象保护 | 原文和附件直链必须鉴权，过期签名不复用 |
| AC-US04-04 | 出域策略 | 禁止外部模型的数据分类不会进入外部模型请求 |

### US-05 治理审计

**验收标准**：

| 编号 | 验收点 | 通过标准 |
|---|---|---|
| AC-US05-01 | 审计查询 | 管理员可按租户、主体、动作、结果、时间和 `trace_id` 查询 |
| AC-US05-02 | 敏感脱敏 | 问题、回答和引用按数据策略脱敏、加密和限权 |
| AC-US05-03 | 质量看板 | M3 起展示问答量、准确率、引用正确率、拒答率和低置信度队列 |

## 4. 非功能验收口径

| 类别 | M1 门槛 | M4 门槛 | 验收证据 |
|---|---|---|---|
| 准确率 | 脱敏评估集首答准确率 ≥80% | ≥85%，且相同评估集不回退 | 评估报告、样本、标注规则 |
| 引用正确率 | 逐题人工抽样，P0 错引清零 | 目标值在 M1 评审冻结 | 引用核验表 |
| 拒答 | 证据不足题必须拒答 | 拒答率与幻觉率同时跟踪 | 对抗样本报告 |
| 延迟 | 记录首事件、首 delta、完整回答和各阶段空闲 P95 基线 | 首事件 P95 ≤2 s、首 delta P95 ≤5 s、完整回答 P99 ≤60 s，或以评审冻结值为准 | 压测报告、trace、流指标 |
| 安全 | P0 越权用例为 0 | M2/M5 安全专项通过 | 权限测试、渗透和审计抽样 |
| 可恢复 | M1 保证失败任务可重试 | M4 完成备份恢复演练 | 恢复报告、RPO/RTO |

## 5. 提测准入与验收退出

### 提测准入

- 需求、API、数据模型、错误码、UI 状态和测试用例已更新。
- 影响 `FR-AC-*`、`FR-QA-05`、审计、密钥或外部模型出域的变更已经安全评审。
- 测试环境使用脱敏数据，不含真实凭据和生产截图。
- 每个可演示流程至少包含成功、失败、无权限、空数据和重试路径。
- 流式问答演示必须覆盖首 token 前取消、已有输出后取消、取消后重发、重复/倒序事件和代理断连。
- v2 灰度前 API、状态机、数据迁移、SLO、回滚开关和相关 `Skill refs/MCP refs` 已同步。

### 验收退出

- P0 缺陷为 0；P1 缺陷必须有 Owner、风险说明、缓解措施和截止版本。
- 所有关联 FR 都有测试证据；无法自动化的项目必须有手工记录和截图或日志。
- RAG 评估报告、权限专项报告、发布清单和回滚方案齐全。
- 未关闭开放问题不阻塞当前里程碑，且已在决策记录中降级或拆分。

---

_MVP 的验收重点是“可追溯、不过权、可恢复、可测量”。任何看似提升体验但削弱这四点的变更，都必须先进入决策记录。_
