# EKB 全前端视觉改版实施文档

> **状态：本文件已被 v2.0 替代，不再作为实施依据。** 请改用 [`EKB 全前端重建实施文档 v2.0`](./EKB全前端重建实施文档_v2.0_2026-08-09.md)；v2.0 明确采用全新 `app-v2` 目录从零重建，旧页面、旧组件、旧 CSS 和旧布局不再作为基础。

> 版本：v1.1
> 日期：2026-08-09
> 视觉真值：`设计稿/index.html`
> 目标：工作台、知识库、AI 助手、检索中心和数据看板全部统一为设计稿的浅色企业知识工作台 UI；放弃原有 Dify 风格视觉，但保留现有 API、状态管理和业务能力。

## 1. 改版原则

- 全站只保留 `App.tsx` 提供的一套全局侧栏和顶部工具栏，业务页面不得再次渲染品牌侧栏、应用导航、全局面包屑或用户栏。
- 视觉统一使用冷白/浅灰背景、深蓝正文、蓝色主操作、绿色成功状态、细边框、小圆角和轻阴影。
- 页面组件统一信息密度、按钮高度、表格行高、空态、加载态、错误态、焦点态和响应式行为。
- 业务页可以保留迁移期旧 class 作为内部兼容，但最终渲染不得再出现深色、橙紫渐变、炫光、重复应用壳或旧 Dify 视觉。
- 不修改 FastAPI、数据库、认证、权限、SSE、上传、检索和反馈接口，不用静态设计稿替代真实 React 业务页面。

## 2. 现状与问题

`DashboardPage` 和全局应用壳已按设计稿实现，但 `QAPage`、`KbPage`、`SearchPage`、`OpsPage` 仍各自包含大量 `dify-*` 页内 UI：独立品牌侧栏、旧顶栏、旧 hero、旧色板和旧卡片。业务页嵌在新全局壳内后形成重复导航和明显视觉割裂。

本次不重写业务数据流，而是拆除这些页内旧壳，重新组织页面 JSX 和样式：

- 保留：props、API 调用、状态、筛选排序、上传删除、SSE、引用、反馈、版本历史等行为。
- 替换：页面结构、视觉 class、布局容器、页头、卡片、表格、工具栏、空态和响应式规则。
- 清理：确认无引用后再删除旧样式；不得为了“清旧 UI”误删仍被其他页面使用的业务样式。

## 3. 页面蓝图

### 3.1 工作台 `#/dashboard`

- 保持设计稿结构：问候与快捷操作、5 张指标卡、趋势图、分布图、最近动态、最近访问、热门标签和健康度。
- 继续完善同视口视觉精度、侧栏折叠和页面跳转。

### 3.2 知识库 `#/kb`

- 页面头：标题、说明、新建知识库、上传文档、前往 AI 助手。
- 概览：知识库数、文档数、会话数和当前库容量。
- 主体：左侧仅作为“知识库选择列表”，不再是第二套应用侧栏；右侧显示当前库信息、文档/检索测试/设置标签页。
- 文档区：搜索、排序、筛选、批量选择、批量删除、上传进度、状态、版本历史和删除操作全部保留。
- 空态：无知识库、无文档、搜索无结果分别提供明确下一步操作。

### 3.3 AI 助手 `#/qa`

- 使用三栏工作区：会话栏、聊天主区、引用与上下文栏。
- 会话栏只承担新建会话、历史列表、分页和清空，不重复品牌、账户或全局导航。
- 聊天区保留知识库选择、欢迎建议、消息流、流式阶段、停止、重试、复制、反馈和输入框。
- 引用栏保留证据列表、路径、版本、相似度和定位能力。
- 小屏下引用栏与会话栏可折叠/下沉，输入框和发送操作始终可见。

### 3.4 检索中心 `#/search`

- 页面头：标题、说明、结果统计和返回 AI 助手。
- 将原左侧旧导航改为页面内横向/卡片式筛选区：知识库范围、时间、文档类型和相关性阈值。
- 主体保留自然语言查询、纯向量检索、排序、结果卡、原文片段和分页/空态。

### 3.5 数据看板 `#/ops`

- 页面头：运行态势、时间范围、数据延迟状态和快捷入口。
- 使用与工作台一致的指标卡、筛选按钮、状态色、卡片和表格。
- 保留问答质量、检索性能、系统健康指标、日志级别筛选、日志表和路线图提示。
- 删除页内运营导航和重复品牌头。

## 4. 路由与能力映射

| 入口 | 路由 | 必须保留的能力 |
|---|---|---|
| 工作台 | `#/dashboard` | 指标、筛选、快捷跳转 |
| 知识库/文档中心 | `#/kb` | 新建/删除库、上传、筛选排序、批量删除、版本历史、测试、设置 |
| AI 助手 | `#/qa` | 会话、SSE 问答、停止、引用、复制、反馈 |
| 全局搜索/检索中心 | `#/search` | 查询、范围/时间/类型/阈值筛选、结果回溯 |
| 数据看板 | `#/ops` | 时间范围、指标、日志筛选和表格 |

团队与权限、应用中心、回收站、收藏和分享等未实现能力不伪造后端数据，继续以禁用或说明状态呈现。

## 5. 串行实施任务

### T1：全局壳与共享规范

- 保持 `App.tsx` 为唯一全局应用壳。
- 建立业务页共享的 page header、toolbar、card、table、tabs、empty/error/loading 视觉规则。
- 业务页错误提示仍保留，Dashboard 不被未启动后端的全局错误覆盖。

### T2：知识库页面

- 拆除页内品牌/面包屑旧壳并迁移到新版双栏内容区。
- 回归新建、选择、上传、筛选排序、批量删除、版本历史、测试和设置。

### T3：AI 助手页面

- 重构为新版三栏工作区，保留全部会话和流式问答逻辑。
- 回归空会话、发送中、取消、失败、引用、反馈和无知识库状态。

### T4：检索中心

- 将旧左栏筛选重组为新版筛选卡/工具栏，统一结果卡和空态。
- 回归查询提交、筛选、阈值和结果排序。

### T5：数据看板

- 删除页内旧导航，统一页面头、指标卡、状态、筛选和日志表。
- 回归时间范围和日志级别筛选。

### T6：清理与验收

- 删除确认无引用的旧样式，避免影响 `DocVersionPanel` 等共享组件。
- 运行构建、差异检查、五路由浏览器回归和同视口视觉 QA。

## 6. 验收标准

### 全局

- 五个路由只出现一套品牌侧栏和顶部工具栏，无重复导航、重复用户区或旧 hero。
- 1181×1027 桌面视口无横向溢出；窄屏不遮挡主操作。
- 主色、字体层级、边框、圆角、阴影、表格和空态与设计稿属于同一视觉系统。

### 分页

- KB：全部知识库/文档操作和版本历史仍可触发，空态清晰。
- QA：会话与三栏布局可用，输入框固定可见，流式阶段、停止、引用和反馈不回归。
- Search：查询及四类筛选可用，结果可读且可回溯。
- Ops：时间和日志筛选可用，指标与日志表在窄屏可读。

### 质量检查

```bash
cd apps/web && npm run build
cd ../.. && git diff --check
```

- 浏览器打开 `#/dashboard`、`#/kb`、`#/qa`、`#/search`、`#/ops`，确认无 React 错误边界和新增控制台异常。
- 测试侧栏收起/展开、全局搜索、各页主要按钮、空态和关键响应式断点。
- 最终视觉证据与结论写入项目根目录 `design-qa.md`。

## 7. 风险与边界

- 当前后端未运行时业务页会显示真实 API 错误；这不应污染 Dashboard，也不应被伪造数据掩盖。
- 四个业务页体量大，必须逐页迁移、逐页构建和浏览器检查，禁止一次性删除全部旧 CSS。
- 工作区存在用户的其他未提交改动；实施只触碰本任务明确的前端文件和本文档，不回滚无关差异。
- 工作台展示数据仍是稳定 demo 数据，不代表新增统计接口。
