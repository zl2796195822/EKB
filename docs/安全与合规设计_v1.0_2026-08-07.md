> **用途**：定义 EKB 的威胁模型、权限边界、出域策略、审计和合规要求。

## 1. 安全目标

| 目标 | 说明 |
|---|---|
| 租户隔离 | 不同租户之间不得互相检索、引用、导出或猜测资源存在性 |
| 最小权限 | 用户、管理员、平台管理员、外部客户都只获得所需权限 |
| 数据不过界 | 受限数据不得进入外部模型、日志、审计导出和截图 |
| 可追责 | 登录、授权、检索、问答、导出、降级、管理操作都可审计 |
| 可恢复 | 误删、模型异常、权限错误和存储故障可恢复或降级 |

安全实现与评审必须读取本地 `security-best-practices`；新增信任边界、数据出域、管理面或攻击面时必须补充 `security-threat-model`。Skill 只提供审查方法，本文档、Spec 和决策记录定义 EKB 的实际控制要求。

## 2. 威胁模型

| 威胁 | 风险 | 主要控制 |
|---|---|---|
| 越权访问 | 读取其他租户的知识、会话、对象或审计 | 服务端授权、租户过滤、对象直链鉴权 |
| 提示注入 | 文档或用户问题诱导模型忽略系统指令 | 系统提示与文档分离、输入审查、红队样本 |
| 数据出域 | 敏感数据被送往外部模型 | 数据分类、路由策略、审计、熔断 |
| 缓存污染 | 一个主体的缓存结果被另一个主体复用 | 缓存键绑定租户和权限摘要 |
| 审计泄露 | 审计日志包含原问题、原答案、密钥或敏感配置 | 脱敏、加密、最小权限、留存控制 |
| 对象直链泄露 | 通过 URL 直接访问未授权原文 | 短期签名、服务端校验、过期失效 |
| 供应链风险 | 组件、模型或镜像版本不可信 | 版本锁定、许可证核验、镜像扫描 |

## 3. 权限模型

### 3.1 身份与租户

- 用户身份可跨租户复用，但必须通过 `tenant_memberships` 绑定具体租户角色。
- 平台管理员的跨租户行为必须显式授权并进入审计。
- 外部客户默认只能访问自己的租户，不存在跨租户浏览路径。

### 3.2 知识库与文档权限

| 权限对象 | 控制点 |
|---|---|
| 知识库 | `OWNER/ADMIN/EDITOR/VIEWER` + `PRIVATE/TEAM/PUBLIC` |
| 文档 | 文档状态、版本、来源、可见范围、软删除 |
| Chunk | `acl_fingerprint`、`tenant_id`、`kb_id`、`doc_id` |
| 会话 | 只返回当前主体可见会话和消息 |
| 导出 | 审批、脱敏、审计、限量 |

### 3.3 检索期授权

检索期授权是系统安全边界的核心，必须满足：

1. 先计算 `AuthorizedScope`，后调用搜索、RAG 和模型。
2. Query Rewrite 不能先接触未授权 chunk 原文。
3. 引用候选集与最终回答必须来自同一权限范围。
4. 缓存、对象签名和导出都要使用同一份授权摘要。

## 4. 出域与模型路由

| 数据等级 | 是否允许外部模型 | 处理方式 |
|---|---|---|
| L0 | 视租户策略而定 | 可路由到外部或本地 |
| L1 | 默认不外发，需审批 | 优先本地，外部受控 |
| L2 | 默认禁止 | 仅本地处理或拒绝 |
| L3 | 禁止 | 不入模型上下文，必要时阻断 |

### 4.1 路由规则

- 路由决策由服务端根据数据分类、租户策略、模型可用性、超时和预算综合决定。
- 所有外部模型调用都要记录模型名、策略版本、租户、数据分类和耗时。
- 当策略禁止外部模型时，系统必须返回可解释拒答或本地降级结果，不能静默调用。

## 5. 提示注入防护

| 层 | 控制 |
|---|---|
| 输入 | 去除明显控制字段、恶意系统提示、伪装指令 |
| 文档 | 将文档文本视为证据，不视为系统命令 |
| Prompt | 系统指令、知识约束、输出约束分层 |
| 输出 | 引用和结论由系统拼装，模型不能编造文档名 |
| 红队 | 建立提示注入样本集并纳入 M2/M4 回归 |

## 6. 审计与留存

### 6.1 审计范围

- 登录、登出、刷新、失败登录。
- 成员变更、角色变更、ACL 变更、权限过期。
- 文档上传、重试、删除、版本切换、只读同步。
- 问答、检索、拒答、降级、引用、反馈。
- 管理员导出、模型策略修改、租户创建、配额修改。

### 6.2 审计字段

| 字段 | 说明 |
|---|---|
| `action` | 统一动作名 |
| `target_type` / `target_id` | 操作对象 |
| `result` | 成功、失败、拒绝、降级 |
| `trace_id` | 跨服务追踪 |
| `metadata_redacted` | 脱敏后的补充上下文 |

### 6.3 留存原则

- 审计默认不可静默修改。
- 敏感内容按数据策略脱敏或加密。
- 导出需审批，且导出本身也要审计。
- 到期清理必须按合规政策执行并记录结果。

## 7. 密钥与凭据

| 项 | 要求 |
|---|---|
| 存储 | 不在仓库和普通日志里保存明文密钥 |
| 引用 | 只保存 `secret_ref`、`endpoint_ref` 或受控清单编号 |
| 注入 | 通过环境变量、密钥管理服务或受控部署清单注入 |
| 轮换 | 历史暴露过的凭据立即轮换 |
| 访问 | 最小权限，运维与开发分离 |

## 8. 备份与灾备

- 业务库、索引元数据和对象存储都要可恢复。
- 备份文件本身要加密并限制访问。
- 恢复演练需覆盖误删、单库损坏、对象存储故障和配置损坏。
- 恢复结果要记录 `RPO/RTO`、演练日期、操作者和缺陷。

## 9. 安全评审清单

- [ ] 越权测试覆盖租户、知识库、文档、chunk、引用、导出和缓存。
- [ ] 提示注入样本不会突破系统指令或读取未授权证据。
- [ ] 外部模型调用前已做数据分类和策略判断。
- [ ] 审计可追踪但不过度暴露敏感内容。
- [ ] 密钥和证书只通过受控渠道进入系统。

---

_安全设计的基本态度是默认不信任：不信任前端、不信任文档文本、不信任缓存、不信任外部模型。_
