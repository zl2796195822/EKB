## 1. 环境分级

| 环境 | 目的 | 约束 |
|---|---|---|
| dev | 开发联调 | 可频繁重建，使用脱敏样本 |
| test | 自动化测试 | 稳定可重复，数据固定 |
| staging | 发布前验证 | 接近生产，演练回滚和恢复 |
| prod | 线上服务 | 严格审批，变更可审计 |

## 2. PoC/MVP 部署

### 2.1 Docker Compose

PoC 和小规模内测建议一套可重复的 Compose 部署，包含：

- web
- api
- rag
- postgres
- redis
- object-storage
- 本地模型服务或经审批的外部模型代理

### 2.2 部署要求

| 项 | 要求 |
|---|---|
| 配置 | 所有连接串、Token、密钥通过环境变量注入 |
| 日志 | 结构化日志，含 `trace_id`、租户、动作、状态 |
| 健康检查 | API、数据库、RAG、对象存储都要有健康探针 |
| 版本 | 镜像和依赖版本冻结，避免“本地能跑” |
| 数据 | 只用脱敏样本或 PoC 样本 |

## 3. 生产强化

### 3.1 触发条件

| 触发 | 动作 |
|---|---|
| 并发或容量不足 | 引入横向扩展、消息队列或更强的索引组件 |
| 发布频率提高 | 规范化 CI/CD、蓝绿或滚动发布 |
| 恢复要求提高 | 独立备份、恢复演练和故障分区 |
| 安全审计要求提高 | 强化日志留存、审批和告警 |

### 3.2 运维边界

- 运维负责环境、镜像、证书、监控、备份、恢复、回滚和值守。
- 开发负责镜像构建、健康检查、迁移脚本和回滚兼容性。
- 安全负责策略、审计、密钥和出域边界。

## 4. 配置与密钥

| 配置项 | 形式 | 说明 |
|---|---|---|
| 数据库连接 | `EKB_DB_URL` | 不写明文到仓库 |
| Redis 连接 | `EKB_REDIS_URL` | 缓存与任务使用 |
| 对象存储 | `EKB_S3_*` | 存储文档和附件 |
| 模型端点 | `EKB_MODEL_*` | 本地或受控外部端点 |
| 密钥引用 | `secret_ref` | 应用内只保存引用，不保存明文 |

## 5. 监控与告警

### 5.1 必备指标

| 类别 | 指标 |
|---|---|
| API | QPS、错误率、P95/P99、SSE 断流率、首事件/首 delta/完整回答延迟 |
| Conversation Stream v2 | 各阶段耗时、`finish_reason`、取消成功率、心跳超时、重复/倒序事件、协议解析错误 |
| RAG | 召回率、rerank 命中率、拒答率、幻觉率 |
| 任务 | 入库成功率、失败率、重试次数、队列积压 |
| 存储 | 数据库连接数、慢查询、对象存储错误率 |
| 安全 | 越权拒绝数、出域阻断数、审计导出数 |

### 5.2 告警规则

- 登录失败激增。
- 文档入库失败率超过阈值。
- 问答上游超时或降级率升高。
- `error+timeout` 占比 5 分钟超过 5%，首 delta P99 超过 5 秒，或协议错误率超过 0.5%。
- 取消接口出现越权、终态重复或 turn 状态长期停留 `cancelling`。
- 越权拒绝数异常波动。
- 备份作业失败或恢复演练失效。

## 6. 备份策略

| 对象 | 频率 | 保留 | 说明 |
|---|---|---|---|
| PostgreSQL | 每日全量 + 增量 | 按合规期限 | 含业务、审计和任务元数据 |
| 对象存储 | 每日或按对象生命周期 | 按知识策略 | 文档和附件 |
| 配置 | 变更时保存 | 版本化 | 不含明文密钥 |
| 评估集 | 版本更新时 | 长期 | 用于回归对比 |

### 6.1 SQLite 阶段备份（M1/M4 当前）

M1/M4 当前用 SQLite（业务库+索引元数据合一，对象存储原文未落盘），备份脚本已落地：

| 对象 | 脚本 | 频率 | 保留 | 校验 |
|---|---|---|---|---|
| SQLite 业务库 | `scripts/backup.py` | 按需/定时 | 7 份 | sha256 + 行数一致性 |
| SQLite 恢复 | `scripts/restore.py` | 演练/故障 | - | sha256 校验 + 恢复后行数校验 |

- 备份用 `VACUUM INTO` 在线一致性快照，不阻塞写入。
- 恢复前自动备份当前库（防误恢复）。
- admin API `POST /api/v1/admin/backup` 支持在线触发（平台管理员能力）。
- **演练记录**（2026-08-08）：RPO=0（一致性快照）；RTO=0.057s（文件级恢复）；备份 0.069s；恢复后行数一致校验通过。

## 7. 恢复与回滚

### 7.1 恢复顺序

1. 恢复数据库。
2. 恢复对象存储。
3. 恢复索引/向量数据。
4. 校验文档状态、会话和审计。
5. 重新跑最小问答和权限测试。

### 7.2 回滚原则

- 先回滚应用，再回滚配置，最后处理迁移。
- 破坏性迁移必须有前向兼容窗口和回滚脚本。
- 回滚不应破坏审计和留存。
- Stream v2 使用 feature flag 灰度；触发 P0 越权/错引、重复消息率 >0.1% 或 SLO 连续 15 分钟不达标时，关闭 v2 flag 并保留 v1 客户端路径。
- 回滚期间已生成的部分回答和取消审计不得删除；恢复后先执行单轮成功、取消和权限 smoke test。

## 8. 值守与应急

| 场景 | 处理步骤 |
|---|---|
| 大面积问答失败 | 触发降级，切本地模型或返回受控拒答 |
| 数据库异常 | 暂停写入、保护数据、执行恢复预案 |
| 对象存储异常 | 停止上传和预览，保持已存在内容可读 |
| 权限配置错误 | 冻结管理操作，回放最近变更 |
| 密钥泄露 | 立即轮换、检查访问日志、阻断可疑流量 |
