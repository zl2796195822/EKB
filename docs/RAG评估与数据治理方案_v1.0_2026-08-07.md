# EKB RAG 评估与数据治理方案

> **配套文档**：[企业级知识库 Spec](./企业级知识库Spec_v1.0_2026-08-07.md) · [技术架构与详细设计](./技术架构与详细设计_v1.0_2026-08-07.md) · [安全与合规设计](./安全与合规设计_v1.0_2026-08-07.md)  
> **文档版本**：v1.0（待评审）  
> **编写日期**：2026-08-07  
> **用途**：定义知识入库治理、切分策略、评估集、指标公式和 RAG 质量门禁。

---

## 1. 治理目标

| 目标 | 说明 | 对应需求 |
|---|---|---|
| 知识可追溯 | 每个回答能追到文档、版本、章节、chunk 和更新时间 | `FR-QA-02` |
| 权限不过界 | 检索、上下文和引用只使用授权 chunk | `FR-QA-05`、`FR-AC-01` |
| 无依据拒答 | 证据不足时拒绝编造 | `FR-QA-03` |
| 质量可测 | 准确率、引用正确率、拒答率、幻觉率有固定口径 | G2、NFR |
| 数据可治理 | 来源、Owner、分类、版本和下线流程明确 | `FR-KB-*` |

## 2. 数据分级

| 等级 | 示例 | 外部模型策略 | 入库要求 |
|---|---|---|---|
| L0 公开 | 已公开产品手册、公开 FAQ | 可按租户策略允许 | 保留来源和更新时间 |
| L1 内部 | 内部 SOP、培训材料、通用故障手册 | 默认本地模型；外部需审批 | 标注 Owner 和可见范围 |
| L2 敏感 | 客户配置、工单、故障复盘、账号线索 | 默认禁止出域 | 强制脱敏、限权、留存策略 |
| L3 严格受限 | 密钥、证书、密码、个人敏感信息 | 禁止入库或必须脱敏后入库 | 原文不得进入 RAG 上下文 |

L3 数据若被上传，应进入阻断或人工审核，不得索引和问答。

## 3. 入库规范

| 项 | 规范 |
|---|---|
| 来源 | `UPLOAD`、`URL`、`SYNC` 三类；M3 同步源只读 |
| Owner | 每个知识库和高价值文档必须有业务 Owner |
| 元数据 | `tenant_id,kb_id,doc_id,version,source_type,section_path,tags,updated_at,visibility,acl_fingerprint` |
| 去重 | 文档级 checksum + chunk 级 content_hash |
| 状态 | `PROCESSING`、`READY`、`FAILED`、`DELETED`；非 READY 不参与检索 |
| 版本 | 回答引用绑定文档版本，历史回答可复核 |
| 失败 | 保留失败原因、trace_id、解析器版本和重试入口 |

## 4. 切分与索引策略

### 4.1 起始参数

| 参数 | PoC 起点 | 调整依据 |
|---|---:|---|
| chunk size | 600–800 token | 引用正确率、召回率、答案完整性 |
| overlap | 80–120 token | 跨段落问题召回 |
| top_k 初筛 | 20–50 | 延迟和召回 |
| rerank top_n | 5–10 | 引用质量和生成成本 |

这些值不是固定承诺，M0/M1 必须在评估集上调参。

### 4.2 文档结构处理

- PDF/Word：保留标题层级、页码、段落、表格说明和列表编号。
- Excel：按工作表、表头、行块切分，保留列名和业务主键。
- PPT：按页、标题、讲稿备注和图文 OCR 结果切分。
- 图片/OCR：记录 OCR 置信度，低置信度进入审核或标记。
- 网页：保留 URL、标题、发布时间、正文区域和抓取时间，去除导航与广告噪声。

## 5. 在线 RAG 策略

```text
授权范围 → 本地规范化 → 可选 Query Rewrite → 混合检索 → RRF 融合
→ Rerank → 上下文构建 → 受控生成 → 系统引用 → 评估/审计
```

| 步骤 | 规则 |
|---|---|
| 授权范围 | 任何模型调用前先解析 `AuthorizedScope` |
| Query Rewrite | 只在数据策略允许时执行；不得把 L2/L3 原文发给外部模型 |
| 混合检索 | 向量和关键词都必须带租户、知识库、文档状态和 ACL 过滤 |
| 上下文构建 | 去重、按证据密度排序、限制 token、保留章节路径 |
| 生成 | Prompt 明确“仅依据证据回答”；证据不足返回拒答 |
| 引用 | 由系统根据 chunk 生成，模型不得自由命名来源 |

## 6. 评估集设计

| 集合 | 内容 | 最小规模建议 | 用途 |
|---|---|---:|---|
| Golden QA | 有标准答案和支持引用的问题 | M1 ≥100 题 | 准确率、引用正确率 |
| No-answer | 知识库无依据或权限不足的问题 | M1 ≥30 题 | 拒答率、幻觉率 |
| Permission | 不同租户/角色/ACL 的问题 | M2 ≥50 组 | 越权测试 |
| Freshness | 文档版本变化和过期知识问题 | M3 ≥30 题 | 版本和缓存失效 |
| Adversarial | 提示注入、恶意文档、越权诱导 | M2 起持续 | 安全红队 |

评估样本必须脱敏，保留标注人、标注日期、适用知识版本和预期引用。

## 7. 指标公式

| 指标 | 公式 | 通过解释 |
|---|---|---|
| 首答准确率 | 正确且有证据的首轮回答数 / 有答案题总数 | 结论正确、未越权、引用支持结论 |
| 引用正确率 | 支持结论的引用数 / 展示引用总数 | 引用片段包含回答所需依据 |
| 拒答率 | 正确拒答数 / 应拒答题总数 | 无依据或无权限时不编造 |
| 幻觉率 | 编造或引用不支持结论的回答数 / 总回答数 | 越低越好；P0 幻觉需分析 |
| 检索召回率 | 命中标准证据的题数 / 有答案题总数 | 用于调 chunk 和检索 |
| 首事件延迟 | 服务端收到请求到首个 SSE 有效事件 | 区分检索状态和 token |
| 完整回答延迟 | 服务端收到请求到 `done` 事件 | 与模型、top_k、上下文长度绑定 |

## 8. 质量门禁

| 阶段 | 门禁 |
|---|---|
| M0 | 跑通最小评估脚本，输出样本、模型、切分参数和基线结果 |
| M1 | 首答准确率暂定 ≥80%；证据不足题必须拒答；引用错误进入 P0/P1 缺陷 |
| M2 | Permission 集合零越权；提示注入样本不得突破系统指令和权限 |
| M3 | 反馈、低置信度审核、版本更新和降级事件进入运营闭环 |
| M4 | 评估集扩充后准确率目标 ≥85%，引用正确率和拒答率不回退 |

## 9. 反馈闭环

```text
用户反馈 → 质量队列 → 人工标注 → 根因分类
→ 数据修复 / 切分调整 / Prompt 调整 / 权限修正 → 回归评估
```

| 根因 | 处理方式 |
|---|---|
| 文档缺失 | 通知知识 Owner 补充或标记盲区 |
| 文档过期 | 下线旧版本或更新来源 |
| 切分不当 | 调整 chunk 策略并重建索引 |
| 检索失败 | 调整 BM25/向量/RRF/Rerank 参数 |
| 生成幻觉 | 调整 Prompt、阈值或拒答策略 |
| 权限错误 | 立即安全修复并回放权限测试 |

## 10. 评审清单

- [ ] 所有评估数据均脱敏，且不含真实密钥、口令和客户敏感配置。
- [ ] 每次模型、Prompt、切分、Rerank 或索引变更都有版本和对比结果。
- [ ] 评估报告能复现：数据版本、参数、模型、时间、脚本和结果齐全。
- [ ] 低置信度和负反馈不会自动修改生产知识。
- [ ] 外部模型调用样本经过数据分级和出域策略检查。

---

_RAG 的质量不是一次调参完成的，它是一套持续治理系统：数据、权限、检索、生成和人工反馈必须一起闭环。_
