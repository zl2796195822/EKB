# EKB · 企业智能知识库平台

EKB 面向企业内部员工和外部运维客户，提供带来源引用的 AI 知识问答、文档管理、全文/语义检索和多租户权限隔离。项目采用私有化部署优先、开源组件适配与业务能力自研相结合的路线。

## 当前定位

- **核心价值**：在授权范围内，把分散的制度、SOP、运维手册、案例和客户资料转化为可检索、可追溯的问答能力。
- **首发场景**：内部运维知识问答与外部客户专属知识服务。
- **安全底线**：租户隔离、检索期权限过滤、引用可追溯、敏感数据可不出域、全链路审计。
- **当前状态**：文档基线已补齐，M1 tracer bullet 已完成本地静态验证；业务、研发、安全与运维负责人仍需完成 M0/M1 评审，文档中的指标和组件版本在评审时冻结。

## 技术基线（MVP 建议）

- 前端：React + TypeScript + Vite，SSE 流式问答；组件底座以 shadcn/ui + Tailwind 为候选基线。
- 业务/API：Python FastAPI 模块化单体，承载认证、租户、权限、知识库、会话、审计和配额。
- AI/RAG：RAGFlow 作为可替换的解析、检索和生成适配层；业务层通过内部 API 调用，不把引擎接口暴露给租户。
- 数据：MVP 默认 PostgreSQL + pgvector、Redis、S3 兼容对象存储；只有在规模或检索能力验证后再引入 Elasticsearch、Milvus 或独立队列。
- 模型：本地模型优先，外部 OpenAI 兼容 API 作为受策略控制的降级通道；所有密钥通过环境变量或密钥管理服务注入。
- 部署：PoC/小规模使用 Docker Compose；生产强化阶段再评估 Kubernetes、Milvus 和多卡推理。

> 组件名称、许可证、模型效果和性能均不是永久承诺。正式交付前必须固定依赖版本、核验许可证，并用项目评估集验证效果。

## 启动前必须完成

1. 在 M0 评审中冻结前端、业务层、RAG 引擎适配方式、首批数据源和部署模型。
2. 建立脱敏的问答评估集，明确准确率、引用正确率、无依据拒答率和延迟的测量口径。
3. 把真实服务器地址、域名、账号、口令、API Key 和证书放入受控的部署清单或密钥管理服务，不写入仓库文档。
4. 将 [项目决策记录与开放问题](./docs/项目决策记录与开放问题_v1.0_2026-08-07.md) 中的 M0/M1 问题转换为带 Owner、截止时间和决策证据的事项，再进入 M1。
5. 开始任一研发任务前，按 [开发 Skills 与使用规范](./docs/开发Skills与使用规范_v1.0_2026-08-07.md) 读取本地 `Skills/<skill>/SKILL.md`；任务完成时在变更说明中记录实际使用的 skills、测试证据和未采用项的理由。
6. 按 [文档治理与研发交付规范](./docs/文档治理与研发交付规范_v1.0_2026-08-07.md) 建立任务到需求、设计、测试和发布证据的追踪链，再进入 M1 实现。
7. 涉及浏览器验收、GitHub 协作或 PostgreSQL 检查的任务，按 [MCP 工具与项目使用规范](./docs/MCP工具与项目使用规范_v1.0_2026-08-07.md) 填写 `MCP refs`，默认只读并保留验证证据。

## 本地开发

后端使用 Python 3.9+，前端使用 Node.js/npm。首次运行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e 'apps/api[dev]'
npm install --prefix apps/web
```

启动 API：

```bash
EKB_ENV=development \
EKB_DEV_USER_EMAIL=admin@example.com \
EKB_DEV_PASSWORD=change-me-local-only \
.venv/bin/uvicorn ekb_api.main:app --app-dir apps/api --host 127.0.0.1 --port 8000
```

启动 Web：

```bash
npm run dev --prefix apps/web -- --host 127.0.0.1 --port 5173
```

浏览器打开 `http://127.0.0.1:5173`。当前实现是 M1 tracer bullet，只能用于本地验证，不能直接用于生产。

## 开发技能规则

`Skills/` 保存经筛选的第三方开发参考，不会随产品一起运行，也不能替代项目设计。Spec、安全与合规设计、API 契约、数据模型和测试门禁优先于任何 skill；出现冲突时，按项目文档执行，并在 Backlog 或决策记录中说明差异。

开发人员只能引用项目内已核验的本地快照。执行 skill 中的脚本、安装命令或外部请求前，先检查其作用范围、依赖和敏感数据边界；不得把真实租户数据、密钥或生产地址传给第三方服务。

`MCP/` 只提供受控的研发辅助工具。使用前必须读取 [MCP 工具与项目使用规范](./docs/MCP工具与项目使用规范_v1.0_2026-08-07.md)，按 Backlog 的 `MCP refs` 选择工具；MCP 输出不能绕过鉴权、审计、测试或人工审批，生产环境不得依赖 MCP。
